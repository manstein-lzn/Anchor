# 跨运行程序性经验的验证与迁移

研究日期：2026-09-11。范围：仅评议用户转述的白皮书主张，未获得白皮书全文；不推断其术语的正式定义。共提交 5 个搜索查询，另直接读取原论文；前四个查询工具未返回可见结果。未使用子代理，仅修改本文件。以下区分论文事实与本报告建议，不构成系统性文献综述。

## 核心判断

“完全不知道为什么运行 A 的经验可以在 B 中被信任”过强：已有成功检查、跨任务评估、经验修订删除和候选优化的研究先例 [1–5]。但“有迁移收益”不等于“每条经验都真”，更不等于“在任意新环境都适用”。真正尚未由这些证据解决的是：如何对单条经验给出可校准、可随环境变化更新的适用性与增益保证。

## 原始研究及证据边界

### [1] Reflexion：反馈驱动的重试，不是普遍迁移证明

论文用语言反馈和情节记忆影响后续尝试，不更新模型权重；反馈可以来自环境，也可以内部生成。它提供经验改善行为的基础先例，但应主要理解为同任务后续尝试的改进，不能直接充当任意跨任务、跨环境迁移的证据。反思文字是诊断假设，而非经证明的因果解释。

来源：Shinn et al., *Reflexion: Language Agents with Verbal Reinforcement Learning*，2023，摘要；跨任务区别亦见 [3] §4.5。
URL：https://arxiv.org/abs/2303.11366v4

### [2] Voyager：入库前执行检查，入库后选择性复用

技能为可执行代码；通过环境反馈、执行错误和 GPT-4 成功检查迭代，检查通过后入库。描述嵌入用于检索 top-5 技能；论文评估新世界中的新任务。这里已有“执行、检查、存储、迁移”的闭环，且向量检索与技能学习共存。

限制：成功检查仍可能误判，作者明确承认这一点；Minecraft 内的新世界不等于任意领域，代码可执行不等于所有前置条件下都正确。

来源：Wang et al., *Voyager: An Open-Ended Embodied Agent with Large Language Models*，2023，§2.2–2.3、§3.3、§4。
URL：https://arxiv.org/html/2305.16291v2

### [3] ExpeL：跨任务学习及明确删除先例

从训练任务成功/失败轨迹抽取 insights，在评估任务结合 insights 与 FAISS 检索示例；采用四折验证，也研究源域知识经目标域示例调整后的迁移。经验支持 ADD、EDIT、UPVOTE、DOWNVOTE：初始计数为 2，降至 0 即删除。

限制：投票是 LLM 判断，不是单条规则的独立效用检验；整体收益不能归因于每条 insight。“finetune insights”是改写文本，不是更新模型权重。这是可修订、可退休的经验库先例，而非真值认证。

来源：Zhao et al., *ExpeL: LLM Agents Are Experiential Learners*，2023/2024，§4、Algorithms 2–3、§5.1。
URL：https://arxiv.org/html/2308.10144v3

### [4] MemP：成功过滤、失败修订，以及不能忽略的负面指标

MemP 比较程序性记忆的构建、向量检索和更新。其 Validation 指只保留成功任务轨迹；Adjustment 在使用记忆后执行失败时修订记忆。文中提出删除/弃用，但已列出的更新实验主要是追加、成功过滤、修订，不能把概念性删除公式当成充分验证的自动退休算法。

限制：在线测试更新须与冻结记忆的 held-out 测试区分。Table 1 中 GPT-4o 的 TravelPlanner 硬约束分数从无记忆 12.88 降至 Proceduralization 9.76，尽管其他指标改善；因此“所有指标均受益”不成立。

来源：Fang et al., *MemP: Exploring Agent Procedural Memory*，2025，§Memory Update、Table 1、Eq. 7；以上限定为 v1。
URL：https://arxiv.org/html/2508.06433v1

### [5] GEPA：比自我赞同更强的候选效用选择

GEPA 用反馈轨迹提出提示词改动，先比较同一 minibatch 的改动前后分数，改善后评估 D_pareto；按逐实例表现保留互补候选进入后续选择。最终返回验证集平均分最佳候选，测试集在优化期间保持隔离。

限制：D_pareto 参与反复选择，不是最终独立测试集；谱系追踪说明改动来源，评分才说明观察到的效用。候选退出选择前沿不等于永久删除记忆；这是提示词/系统配置优化先例，不是单条程序性经验通用认证。

来源：Agrawal et al., *GEPA: Reflective Prompt Evolution Can Outperform Reinforcement Learning*，2025，Algorithms 1–2、§4；核对 v1 PDF。
URL：https://arxiv.org/pdf/2507.19457v1

## 对白皮书主张的精确修订

以下为基于上述研究的分析，而非论文直接给出的定理。

1. **溯源不是真值。** 运行 ID、原始轨迹、奖励、评估器版本和生成模型说明“这条经验如何产生”，支持审计与重放。它们不证明摘要忠实、不证明成功由该规则导致，也不证明目标环境满足前提。应分开记录轨迹事实、推导假设、适用范围与测试结果；[2] 的可误判检查和 [5] 的谱系/评分分离说明这一区别的重要性。

2. **Held-out utility 不是 universal validity。** 在未用于构建或选择的任务上，相对无经验基线有收益，只支持该测试分布及设置下的系统效用判断。它不认证每条经验，也不保证任意 B。建议进一步区分：同任务重试、同域新任务、新环境、跨模型、跨领域。不能把这些迁移强度混写。[1–5]

3. **检索不是优化，但不能据此否定所有非参数学习。** 固定库上的一次近邻查询没有更新经验内容或选择策略；它是访问操作。若反馈持续改变可复用文本、代码或选择策略，并经独立任务验证行为改善，则可称系统层面的非参数学习或优化，不必要求模型权重变化。ExpeL 和 GEPA 的构建/更新过程不能压缩成“只是检索”。[3,5]

4. **“经验应饱和”需要操作定义。** 若指有限分布下边际增益趋近零，可作为待检验假设；若指经验库必须达到固定完备状态，或每条规则都永久有效，本次证据不支持。任务覆盖率、库存容量、性能平台期是三个不同量。建议以固定任务分布及成本预算下的边际净收益定义停止扩充条件，而非预设知识终局。[2,4,5]

5. **自动调用不等于无条件全量注入。** 可以让每次运行自动执行经验选择流程，但应允许结果为空。默认评估适用性与“永远注入全部历史经验”不是同一设计；[2,3] 的选择性检索提供替代先例，[4] 的指标下降提醒必须监测负迁移。相关经验仍须通过权限、版本和资源条件检查。

6. **“跨运行排斥向量”需拆开解释。** 若指全面否定向量检索，[2–4] 提供直接反例；若指不能只因嵌入距离远就永久判某经验无效，这一谨慎判断合理，但本次未找到直接检验该特定拒绝策略的实验。相似度至多是候选相关性信号，不是真值、因果或兼容性检验。建议结合语义召回与工具/API、版本、前置条件等结构化门控，而不让单一向量阈值承担退休决策。

## 建议的验证与退休协议

本节是工程建议，不宣称已由任何单篇论文完整验证。

- **候选隔离：** 将新经验先标为候选，保留轨迹、适用任务族、环境/工具版本、成功判据与反例；原始证据和抽取规则分开存储。
- **增量效用：** 同模型、工具、预算和任务条件下，比较无经验、仅检索、经验注入、经验优化四种设置。要评估单条经验，另做有/无该条的配对消融；整体库增益不替代逐条分析。
- **数据隔离：** 构建集、选择集、最终测试集分开；按任务模板、时间或环境划分以减少近重复泄漏。在线学习按时间顺序报告，不能称为全程冻结的独立测试。
- **指标与晋升：** 同时记录成功率、硬约束违规、成本、延迟及分组退化，给出重复运行的不确定性。仅在预先定义的适用域与风险条件内晋升为默认可用。
- **退休而非抹除：** 区分暂不召回、隔离、被新版本替代和永久删除。前置条件失效或重复负效用可触发降级；单次失败只触发调查，因为失败可能来自环境或执行器。保留证据与回滚版本。
- **持续复验：** 模型、工具或环境升级后重新验证；定期对低频经验抽样复验，避免把“未被召回”误当作“无用”。

## 可替换的白皮书表述

“跨运行经验迁移已有程序化技能复用、反思记忆、跨任务经验抽取和反馈驱动优化等先例。但一次成功与可追溯来源不足以确立经验在新运行中的适用性。经验应作为带前置条件、效用证据与版本的可撤销假设，通过独立任务评估、条件化调用和持续修订获得有限范围内的信任；向量检索是候选访问机制，而非真实性或淘汰判据。”

## 研究限度

这 5 篇原始研究足以否定“毫无先例”，不足以证明最优退休政策、必然饱和、全量投影优越性或通用安全迁移。最清楚的删除机制来自 ExpeL，但属启发式投票；较强的验证选择来自 GEPA，但对象是系统候选。没有运行复现实验，没有获取白皮书全文，也没有穷尽 2026 年研究；检索出现的非原始解读和第三方复现未作为证据。
