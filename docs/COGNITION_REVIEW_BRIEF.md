# 认知层评审简报

**给外部评审 Agent 的阅读指引。**

你被要求评审的不是代码，是一套**尚未批准的架构思考**。你的价值不在于赞同，而在于指出它错在哪、缺什么、以及哪些结论是伪装成推理的猜测。

---

## 1. 你的任务

一份白皮书提出：用**状态**（而非摘要）解决 agent graph 长任务下的四个失效——上下文爆炸、注意力稀释、被现象带偏、认知漂移。

请评估：

1. **这个方向是否成立**，还是它只是把问题换了个名字
2. **它明确说"不知道"的三个问题**，是否真的无解，还是已有答案而它没找到
3. **它的边界划得对不对**
4. **最可能的失败方式是什么**

**不要**输出对这套想法的赞同性总结。**要**输出它会在哪里坏掉。

## 3. 文档里没有、但你需要知道的背景

**① 白皮书是思考记录，不是批准设计。** 它的结论未经检验，按它的推论可以被推翻。

**② 当前 Anchor 已经造了什么**（白皮书 §4.3 有清单，但值得强调）：

```
已有：图 IR / 不可变版本 / 租约·attempt·claim / 恢复 / 循环·条件·join
      声明式输入(I8) / 血缘 / 人工等待与审批门 / 收敛判据
      模型调用录制 / 精确回放 / 节点测试台（40 秒一次实验）/ 按节点用量
      交付物确定性检查 / 评审门 / 代码质量门与棘轮
```

**所以"观测仪器"不是待建的——它已经存在并被实测过。** 你的建议应该建立在这个事实上。

**③ 这个项目有记录的失败模式：范围膨胀。**

原始 Anchor 自己的 DON'T 清单里有：

```
vector memory · knowledge graph · scheduler · agent pool
multi-agent governance · reviewer authority · workspace sandbox
automatic per-turn projection LLM · asynchronous Update
parallel state writers · private token budgets
```

**而当前 Anchor 造了其中大部分。** 所以：**如果一个建议把认知层往外扩张，请明确标出它是扩张。**

**④ 有一个待用户决定的问题**（白皮书 §4.7 末尾）：

> `Contract` 在图里由什么承载？运行输入的一部分？图级 metadata？显式新对象？还是由拓扑+节点契约推导？

如果你的分析对这个有看法，那很有价值。

## 4. 要避免的误读

| 容易读成 | 实际是 |
|---|---|
| 又一套 memory / RAG 方案 | 它主张**去验证覆盖面和证据纪律，而不是验证语义正确性**（§2.6）——这是与 RAG 相反的立场 |
| 可以用回放来做策略 A/B | **不能**。回放按位置匹配，改 prompt 必须真实重调模型（ADR-044）。用测试台 |
| 观察者可以改图来自我纠正 | 改图会塌（一个 run 只有一个计划版本）。run 内靠**重做**，run 后靠**改版**（§3.7） |
| 状态能解决上下文爆炸 | **半解决**。它治历史，不治工作集（§3.3） |
| 噪声/统计是核心议题 | 只对**边际改进**成立。本次撞到的全是**明显缺陷**，一次就能看见（§2.7 末） |
| 这三个未解问题只是没做 | **是没解**（§4.3 的 B 类）——工作集、归因、跨 run 验证 |

**特别提醒**：§3.3 是全文最重要的论断——

> **原始 Anchor 把工作集委派给了宿主的 active window，而图没有那个宿主。
> 这才是那个 60% bug 的成因，而它是空的。**

**如果这一条错了，整篇的骨架都要改。请优先对它做批判性检查。**

## 6. 一条方法论要求

这个项目自己的纪律是**失败关闭**：无法解析引用就失败，绝不含糊通过。

**请以同样标准评审**：如果某个论断你无法验证，说"无法验证"，不要给它一个模糊的通过。**无法验证的论断比错误论断更危险，因为它会被当作已确认的前提继续使用。**

原始 Anchor 的那句话在这里同样适用：

> **证书让遗忘可问责，而不假装代码能判断所有自然语言的真假。**

**同理：评审让论断可问责，而不假装评审能判断所有设计的对错。**
