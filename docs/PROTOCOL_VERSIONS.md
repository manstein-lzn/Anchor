# 公开协议的版本策略

Anchor 对外暴露若干协议。**每一个都自带版本号，且每个版本的语义都写在这里**——
因为一个没有版本号的协议，其改动会被下游当作 bug 而不是升级。

## 逐个说明

| 协议 | 版本标记 | 位置 | 版本变更意味着 |
| --- | --- | --- | --- |
| **图 IR** | `IR_VERSION` | `domain/ir.py` | 字段集合或语义变更。图定义会被持久化并 pin 到 run，所以旧版本必须继续可读 |
| **导出包** | `BUNDLE_VERSION` | `domain/bundle.py` | 包结构变更。`import_bundle` 对未知版本**拒绝**，不猜测 |
| **准入消息** | `schema_version: Literal[1]` | `domain/admission.py` | 跨进程投递的消息结构。字面量类型意味着**只有 1 是合法的**；提到 2 需要同时改发布方与消费方 |
| **条件求值器** | `EVALUATOR_VERSION` | `domain/conditions.py` | 取自 jmespath 的安装版本。边决策会记录求值器版本，所以**同一判断在不同求值器下不会被当成同一个判断** |
| **路由求值器** | `ROUTING_EVALUATOR_VERSION` | `domain/propagation.py` | 无条件边与条件边共用同一套决策记录，各自标版本 |
| **模型录制** | `CACHE_FORMAT` / `RECORDING_FORMAT` | `runtime/model_recording.py` | 录制载荷结构。未知版本**拒绝**而不是尽力解析 |
| **内容缓存** | `CACHE_FORMAT` | `runtime/content_cache.py` | 同上：未知版本判为 `corrupt`，回落到真实抓取 |
| **验证器模型适配器** | `MODEL_ADAPTER_VERSION` | `runtime/verifier.py` | 模型裁决的解析规则（严格 JSON 裁定）。进入判断记录，所以裁决可归因到**哪一版解析规则** |
| **MCP 协议版本** | `PROTOCOL_VERSION` | `mcp.py` | 由 MCP 规范决定（当前 `2024-11-05`）。本仓库随规范走 |
| **MCP 服务版本** | `SERVER_VERSION` | `mcp.py` | 本仓库自己的实现版本，与协议版本无关；`initialize` 会报告它 |
| **MCP** | `protocolVersion` | `mcp.py`（上线时为 `2024-11-05`） | 由 MCP 规范决定，不由本仓库决定。本仓库随规范走 |
| **HTTP API** | **无版本前缀** | `api/app.py` | 见下 |

## 为什么 HTTP API 没有版本

**没有稳定的第三方消费者。** 唯一的客户端是 `anchor.client`，它与 API 同仓库、同发布。
给一个只有一个内部消费者的接口加版本前缀，会得到两套端点要维护，而没有任何人因此受益。

**这个判断有前提，前提写在下面**：当出现第一个不在本仓库内的消费者时，无版本就不再成立，
要么给它加前缀，要么明确声明它必须跟进破坏性变更。**在那个时刻到来之前，改动 API 就是改动
`anchor.client` 的同一次提交**——这是可以检查的，也是下面那条测试所检查的。

## 版本变更的规则

```
1. 提升版本号 = 语义变了。
   不提升而改变语义，是把破坏性变更伪装成 bug 修复。

2. 未知版本一律拒绝，不做尽力解析。
   尽力解析会把"我不认识这个"变成"我猜它是这个"。

3. 已 pin 的 run 用发布时的版本解释。
   版本属于被 pin 的工件，不属于此刻的仓库状态。

4. 求值器版本进入决策记录。
   同一条件在不同求值器下可能不同，所以记录必须能区分"判断变了"与"求值器变了"。
```

## 本仓库内的约定

文档与代码里描述状态的词只有三种，含义固定：

| 词 | 含义 |
| --- | --- |
| **已实现** | 有代码，有测试，验收证据在仓库里 |
| **未实现** | 没有代码。若被配置到，应当**显式拒绝**而不是静默回落 |
| **已弃用** | 曾经可用，现在会有明确告知地拒绝 |

**不用** `Completed` / `Target` / `Not yet implemented` / `WIP` 这类词。它们不区分"有代码但没测"
和"有代码也有测"，而这两件事的差别就是能不能信。
