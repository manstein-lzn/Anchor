# 认知状态架构评审

日期：2026-09-11。对象：`COGNITION_ARCHITECTURE.md`，思考记录，非批准设计。
依据：`COGNITION_REVIEW_BRIEF.md` 的 A–G 要求。

## 结论

**不批准按 §4.7 直接建设完整第 2 层。保留“可问责的状态更新”作为待验证假设，重写证据链和推进顺序。**

最关键的三个问题：

1. **“60% 字面重复”不成立。** 相同 evidence 确实出现两次；可直接删除的三个重复字段连同 JSON 包装占 34.92%。所谓 60% 又把包含独有元数据的 `verified_sources` 全算成了重复。
2. **重复的直接机制是反馈对象过宽和输入映射重叠，不是已经证明的“图没有宿主工作集”。** 不引入认知状态即可消除上述 34.92%。
3. **“第 2 层照已有设计做即可”不成立。** 旧项目的独立状态权威、单会话 frontier、全局投影，尚未适配当前 I2 恢复闭包、I8 可见性和图上的多分支输入。

这些问题不证明认知层没有价值；它们证明现有数据尚不能为这套架构的必要性、有效性和实施优先级背书。

## A. 核心论断是否成立

### A1. §1.2 的重复数字：部分事实正确，主结论口径错误

run：`f4eb8ac7-3418-4e8d-8be5-8eaede46e02a`；共 37 条 `node_runs`。

| 核查项 | 结果 |
| --- | --- |
| write attempt 0 的组装 prompt | 141,033 字符，复现 |
| write attempt 1 的组装 prompt | 403,340 字符，复现 |
| `feedback.evidence == evidence` | JSON 值相同；规范化序列化后的同一字符串在 prompt 中出现两次 |
| 一份 evidence | 137,094 字符；266,144 UTF-8 字节 |
| 一份冗余 evidence 占整个 prompt | 33.99%，不是 60% |
| 其他整字段重复 | `feedback.plan`、`feedback.request` 也与顶层相同 |
| 删除上述三份重复字段后 | 262,492 字符，减少 140,848 字符，即 34.92% |
| `evidence.sources` 与 `verified_sources` | 均为 59 项，id 集合相同，四个共有字段值相同；完整对象不相同 |
| `verified_sources` 独有字段 | 包含 abstract、authors、title、year、url、evidence_level、read_truncated 等 |

白皮书的 243,766 正好是 `137,094 + 106,672`。第二项是**整个** verified 列表的长度，而不是与另一列表相同的字节数。相同来源身份不等于相同信息，更不等于整段字面重复。

若再删除 verified 列表，prompt 可降到 155,800 字符，减少 61.37%。但这是一个**下游需求裁剪候选**，不是已经证明的信息无损去重。是否可以删掉其独有字段，需要检查 writer 实际责任与质量影响。

上述 34.92% 是指定字段级操作的确切收益，不是对整个 prompt 做过全局最长重复子串分析后的“总重复率”。“首稿重复 0”同样未经过这种全局核查。字符、UTF-8 字节和模型 token 不应混写。

证据：[`local_audit.json`](../research_cognition_review/local_audit.json)、[`verify_local.py`](../research_cognition_review/verify_local.py)、`node_prompt.py` 的共享组装逻辑。

### A2. 其余五项证据需要拆开来源

| §1.2 条目 | 核查结论 |
| --- | --- |
| 99.9% 缓存命中 | 在本次测试台原输入重跑中复现：173,312 / 173,519。但原始 run 修订轮事件记录的是 67,456 / 173,519，约 38.9%；首稿为 640 / 69,135。不可把事后热缓存当作原运行“每轮”的性质。 |
| 同输入输出 14,544 / 14,573 | 原始成对实验文件未定位，具体数字无法独立验证。本次两个调用的输入不同，不能冒充它的复现。原理上应区分输出不同与质量方差大，字符数差不能量化后者。 |
| 40 秒、46 倍 | 原 run 时间跨度约 1,844.55 秒；本次原输入调用为 48.47 秒。节点级实验确实可运行，但“整轮任务 vs 一个无工具节点”不是同等工作量加速比。 |
| 57%、116 标签、35.5% | ADR-040 记录了这些数值，但未提供足够明确的原输出定位和计数定义供本次复算；标为未验证，不用它支持认知架构收益。 |
| 三轮 0 major、6/6/4 minor 仍 revise | 已核验工件，位于另一个 run `b8fdfc5d-97af-4094-975b-0153e9c43149` 的 attempt 2/6/8。目标 run 则是一轮确定性 major 和一轮 7 minor。白皮书不能把整节统一归于同一个 run。 |

“instructions 仅占 1%”最多是体积比例。当前测试台读到 3,834 字符 instructions，而且它通过独立参数传给模型，不在上述 user prompt 字符数内；这个比例不是模型实际注意力分配的测量。

### A3. 本次真实对照及限制

只从 `feedback` 删除与顶层完全相同的 `evidence`、`plan`、`request`；保留原稿、review 和全部 verified 元数据。保留所有不同的数据值，但字段路径和强调次数发生了变化，不能预设行为等价。

| 指标 | 原输入 | 三字段去重 |
| --- | ---: | ---: |
| prompt 字符 | 403,340 | 262,492 |
| 输入 token | 173,519 | 105,238 |
| 缓存读取 token | 173,312 | 67,456 |
| 输出字符 | 14,379 | 14,667 |
| 模型调用耗时 | 48.47 秒 | 34.71 秒 |
| 结构、行文规则错误 | 0 | 0 |
| 漏引、未知引用编号 | 0、0 | 0、0 |

**允许得出的结论：** 简单输入去重已经有显著的确定性体积收益；本次去重输出没有触发这些有限检查。

**不允许得出的结论：** 质量更好、引用语义正确、费用更低、延迟稳定改善、认知漂移被修复。两组各一次、顺序固定、缓存状态不同，费用字段为 null，也未跑完整语义评审。去重甚至显著增加了本次未命中缓存的输入量，因此不能仅按总 token 推算费用。

另外，两次 CLI 都在打印完整模型结果后以 exit code 1 结束。首轮实验脚本未保存 stderr，无法确诊退出原因；不把它记为 CLI 端到端成功。已将后续复现脚本改为保留 stderr，未修改运行时或用新数据覆盖这两次结果。前后目标 run 的 node_runs 和冻结输入核查未变。

测试台还有已能从代码确认的边界：`frozen_attempt()` 从现行 registry 读取 instructions/tools；CLI 默认不传 memory store，若传入则读取当前 memory，而非冻结当次 memory。目标 run 的 `model.call` 事件为 0。因此复现的是**持久输入快照 + 当前共享组装器/配置**，不是已证实逐字节等同的历史完整请求。I1 的承诺和快照冻结不能替代请求级核对。

证据：[`live_summary.json`](../research_cognition_review/live_summary.json)、`src/anchor/runtime/node_harness.py:143`、`scripts/node_harness.py`。

### A4. “地基修正之后还剩多少”

剩下的是三个独立研究假设：结构化任务状态能否改善接管；显式处置能否减少未察觉的信息遗失；条件化经验能否改善后续任务。§1.2 没有测它们。

失去的是从一个输入重复缺陷，直接推导“需要完整认知内核”“第 2 层应先行”“状态已能解决四类问题”的依据。应把 §1.2 降为**动机与缺陷样本**，不能继续称为全部架构结论的实证地基。

## B. §3.3 的缺口是真的吗

### B1. 有真实的输入选择问题，但成因被过度架构化

本例可直接追踪的链条是：

```text
check 返回整个 snapshot + review + verified_sources
    -> check -> write 边把整个 outputs.check 映射成 feedback
    -> 同一条边又映射其 evidence、plan、request
    -> JSON 序列化自然重复这些子对象
```

冻结图和当前示例图均能核对这组映射；当前 `academic.py:417` 的返回值也解释了宽对象从何而来。

`build_input_snapshot()` 已支持点路径字段选择。于是“下游声明要什么”的基础机制不是空白，当前映射只是声明得太宽。它还没有自动证明读集最小，但这与“没有需求载体”不同。

**反事实检查：** 保持没有 Pi 宿主、没有 Cognition、没有 Checkpoint 的现状，仅收窄输入就能去掉本例已证实的重复。因此，“缺少宿主窗口”不是这个缺陷不可缺少的解释。添加一个窗口也不自动防止边把同一对象传两遍。

### B2. “工作集该住哪”至少是四个不同问题

| 问题 | 对当前项目的最小回答 |
| --- | --- |
| 大材料保存在哪里 | 复用已有不可变工件和内容引用；无需先建新的记忆存储 |
| 节点可以看什么 | I8 和已选入边的声明输入，不能由全局认知库绕过 |
| 一次调用实际加载什么 | 节点输入适配/投影；先用静态字段选择、领域转换，再评估按需读取 |
| 单次工具循环如何避免超过窗口 | 属于节点运行时的上下文管理；不是把整个 run 加一个 State 就能完成 |

对当前无工具 writer，单给 59 个休眠引用没有用：它没有能力解引用。可选择预先物化所需片段，或明确增加受账本管理的读取能力；后者属于**执行能力扩张**，不是免费实现细节。

一个去重后的 59 项账本仍可能太大。这时才需要测分段处理、任务分解、选择性读取及汇总损失。不能把“消除复制”和“压缩任务本身所需信息”合成一个验收指标。

### B3. 已有先例，而且原调查表内部就有反例

- **MemGPT** 已区分工作上下文、消息队列和外存，用函数访问及分页检索管理当前材料；论文也记录提前停止翻页造成检索遗漏。它提供机制，不提供任意任务的充分选择保证。[R1]
- **LangChain 官方上下文工程** 将 select 与 write/compress/isolate 分开，明确讨论每一步的输入选择与图状态。**Anthropic 官方实践**讨论轻量引用和按需加载。这些足以否定领域级“没人解决这一步需要什么”的空白叙述。[R2–R3]
- 白皮书已经列出的 **SoL-Pi ObservationPack** 本身就在做大结果外置和精确分页召回；Reducer 则针对诊断日志选出当前需要的片段。不能列完这些机制又说四者“都只管历史”。[R4]
- 同表中的 **pi-smart-compact** 原文明确描述工作状态、跨会话项目隔离的 FTS5 召回和覆盖验证，并非单纯散文摘要，也不是严格“只在会话内”。其主张仍需行为实验检验，但不能从调查中抹去。[R5]

需要研究的是选择充分性、遗漏风险及本图的集成设计，不是“所有权从未有过答案”。

## C. 三个未解问题的现状

“最好答案”在此解释为最直接、可用于本项目设基线的已知答案，不是未经系统综述得出的全领域排名。

### C1. 工作集

**已有答案：** 分离存储与加载；显式字段选择；按任务/查询召回；分页；程序先过滤后把结果交给模型。[R1–R4、R6]

**尚未证明：** 任意下一步所需的最小充分集合，尤其在尚未看到被遗漏材料时如何判断它重要。休眠条目必须保留足够的发现线索，精确 locator 只回答“怎么取”，不回答“为何想到要取”。

**白皮书漏项：** 工作集与认知不是按内容大小天然分割的对象。同一证据在不同节点可以分别是完整材料、当前约束或休眠引用。节点、任务阶段、权限和版本是投影的输入；只给每个 item 一个全局 active/dormant 标签不足以表达这个差别。

### C2. 归因：需要把三件事分开

1. **故障显现位置：** 哪个节点违反了检查。
2. **因果责任：** 在明确干预条件下，改哪个因素会改变失败。
3. **优化性信用分配：** 哪种参数组合值得保留或继续搜索。

writer 出现错误引用可能来自 gather 的来源身份、coverage 的合并、writer 的转述或 validator 的错误规则。per-node 检查提供故障地址，不提供唯一根因。冻结 writer 输入重试，也不能判断本来没进入该输入的上游证据是否关键。

**已有答案：** DSPy 将语言模型程序模块化并围绕指标优化；MIPRO 明确研究无模块标签/梯度时的多阶段指令与示例联合搜索；TextGrad 将文本反馈传回图中变量；GEPA 从轨迹反思生成修改，再按评价结果选择候选。[R7–R10]

这些方法不是通用因果证明，但已经回答了“如何开始优化多节点参数”。**可靠因果解释不是黑盒改进的必要前置条件。** 若把“归因”泛化为一切反馈利用，可以说优化需要它；却不能再宣称缺少单次根因证明就无法学习。

**最小做法：** 把观察者输出叫“归因假设”，分别记录干预、局部结果与端到端结果；先做一个参数的受控改动，再按需要测相互作用。不建立新的归因核心服务。

### C3. 跨 run 经验验证

**已有答案：** Reflexion 提供反馈记忆改善后续尝试的先例，但主要不能当作任意跨任务迁移；Voyager 将经执行/成功检查的代码技能入库并选择性复用；ExpeL 从训练任务提取经验、在新任务评价，并提供修改、投票和删除操作；GEPA 提供候选配置的验证选择。[R10–R13]

这些证据都没有证明“每条经验在任意 B 中为真”。ExpeL 的删除票数是启发式判断，Voyager 的成功检查也可能出错，GEPA 的候选验证不认证反思解释。**已有有限域效用评估方法；不存在由一次成功直接推导普适有效性的许可证。**

本项目应要求的不是抽象“被相信”，而是：

- 明确作用域、任务族、环境/工具/模型版本和可失效的前置条件。
- 经验构建集、反复选择候选的验证集、最后一次独立测试集分开。被优化器反复访问的“留出集”已经是选择集。
- 比较不用经验与条件化使用经验的效用，同时报告硬约束违规和分组退化；整体库收益不能证明每条规则有益。
- 将负例、版本变化和前置条件失效用于隔离/退役；保留审计记录，不把退役等同于抹除历史。

“自动使用”可以是自动运行选择器且允许结果为空，不必全量注入经验。文本/结构化检索和向量检索都是候选访问机制，既不自动证明真值，也不因跨 run 而自动成为必需。

白皮书自己的三个例子已说明不能无条件泛化：限速值是依赖服务和时间的环境观察；“仅 minor 则批准”依赖已接受的验收契约；“按交付物切节点”是设计启发式。它们不是同一种可以永久自动投影的“经验真值”。

## D. 边界划得对不对

### D1. 四件事中，归因不应成为在线状态内核的前置职责

§4.2 将“归因”纳入核心，§4.1 又把它放在第 4 层；§4.7 再主张先建第 2 层。应明确：在线认知层保留事件/版本/来源关联，离线评估器解释及检验归因假设。不能因为字段都能放进 proposal 就说是同一种语义协议。

run 内认知提交的谓词是身份、覆盖、来源和冲突纪律；跨 run 经验晋升需要效用与适用域证据；配置发布需要权限及验证。它们可以复用不可变内容和事务基础，不能复用同一条“合法即可信”的审批标准。

### D2. 真正缺的是已有边界的接入契约

| 必须明确 | 最小要求；不是另建一套平台 |
| --- | --- |
| 权威与恢复 | 按 I2，接受的认知 revision 必须由控制事件引用不可变内容；latest State 只是物化读视图，不能成为事件史以外的第二恢复权威。所谓“权威”是系统接受的当前判断，不是自然语言事实已经被证明为真。 |
| 可见性与信任 | 按 I8，各节点只投影显式获准的认知/材料；检索到旧文本不取得当前指令权。来源可寻址不代表有权限读取，更不代表其文本能变成政策。 |
| 图上的 frontier | 单会话前后缀不能直接移植。必须明确吸收了哪些分支、attempt 和内容版本，未吸收的证据留在哪里；日志全局序号不等于每个节点的认知覆盖范围。 |
| 更新所有权 | 先使用既有串行边界和版本冲突拒绝；不要让每个完成节点并行重写一份全局 State，也不要在没有实验前新建并行合并协议。 |
| 失效与冲突 | 证据被更正后，相关结论需要重审。先在 item 中保留作用域、来源和显式冲突，不必立即升级为通用知识图谱。 |
| 资源不足 | I6 排除猜测性终止，不排除真实模型窗口。所需信息确实放不下时，必须显式分解、外置或停下询问，不能以“最小充分”之名静默截断。 |

这些约束说明第 2 层并非“照搬即可”。另一方面，以上是集成约束，不构成同时实施六个新子系统的建议。

### D3. Contract 的建议

**逻辑上显式、类型化；物理上先复用当前 Task/run 准入与不可变内容，不新建 Contract 服务。**

本地 Task 已有 `objective`、`constraints`、`success_criteria`，所以 §4.3 的“没有 Contract”应改为“尚未归一并冻结完整 Contract 语义”。

建议把图定义中的默认约束、调用者明确输入和 Task 要求，在准入时归一成一个已接受的 Contract revision，固定引用并纳入 I2；至少区分 goal、acceptance、constraints、non-goals。冲突或缺项显式报告，不由观察者补成用户已批准的要求。

不能仅放在松散 metadata：否则缺少校验和优先级。不能从拓扑推导：同一拓扑可以服务不同目标，图结构无法推导“论文还是审计台账”。也不需要先决定新数据库表才能做去重实验。

验收标准的修改必须由人接受；在明确支持契约修订事件前，默认暂停并通过新 run 使用新契约，不静默改当前 run 的合格定义。

## E. 最可能的失败方式

以下按本次评审判断的相对可能性排序，不是量化发生概率。

| 排名 | 失败方式与依据 | 如何暴露 |
| --- | --- | --- |
| 1 | **为输入映射缺陷建设整层架构。** §4.7 的优先级建立在错误的必要性判断上；最小去重已经能削掉三分之一。 | 与只改映射的基线比，新增状态没有独立收益，成本和维护面却上升。 |
| 2 | **State/Index 变成第二份历史。** §2.2 的反事实问题偏向保守保留，§3.5 又要求经验自动投影；旧条目和恢复线索均会增长。 | 固定任务复杂度下，Active、Index、Update 输入/输出及总 token 随轮次增长；仅测最终 prompt 会漏掉更新成本。 |
| 3 | **带证书的错误变得更难质疑。** 错因被写成因果句并 carry，合法来源被当作语义支持，旧认知成为后续 Update 的前提。 | 注入“测试失败却解释为通过”、无关合法来源、错误重试条件，观察能否一路合规传播。 |
| 4 | **用错误评价优化到错误目标。** §2.7 已承认 loss 难定义，§3.8 又把测试台称为裁决者。 | 局部格式全绿但实际质量下降；minor 标签被错误降级后自动通过；验证集越调越好，独立任务变差。 |
| 5 | **全局认知破坏隔离或 frontier 丢分支。** §3.2 的循环边界和 §3.8 的节点级提交没有规定各自覆盖集。 | 分支 A 的证据被 B 使用而无声明，或一个完成事件使尚未吸收的另一分支被错误跳过。 |
| 6 | **经验负迁移且无法有效退休。** §3.4–3.5 把经验“小、饱和、应泛化”当结构事实。 | 模型/工具/课题变化后，旧规则仍自动生效；整体平均值掩盖某类任务硬约束恶化。 |
| 7 | **失败关闭变成无法继续。** 错误源引用被拒绝是必要纪律，但所有大窗口任务的 Update 一旦持续失败，原窗口也不能无限保留。 | 对更新拒绝、进程恢复和窗口将满组合做测试，检查是否明确保留证据并进入人工处理，而非死循环或静默降级。 |

最可能“长成它要解决的问题”的路线是：为保证不遗漏增加更多 item，为恢复它们增加更多索引，为治理索引增加归因和评审，再把这些产物继续注入上下文。必须把**全链路成本和行为收益**作为约束，不只追求最新投影看起来简洁。

## F. 应该先做什么、最不该做什么

### F1. 顺序：每一步通过后再进入下一步

1. **先修正论断和实验记录。** 区分字面复制、同源不同字段、任务必要工作集；把原 run、其他 run 和事后 harness 的数据分开。本报告提供可复算起点。
2. **只在学术图收紧反馈输入。** 保留一份 evidence、原稿和必要 review；对 verified 元数据做独立需求审查。使用已有点路径映射或领域输入适配，不先建通用投影语言。为字段保留和大小变化加回归断言。
3. **先把现有测试台作为可信实验入口。** 保存实际 instructions/模型/配置摘要、输入和输出版本；明确 memory 冻结范围；解决结果输出后非零退出的可观测性问题。复用已有录制与测试能力，不重建观测平台。
4. **做认知层的独立接管实验。** 比较完整历史、普通结构化摘要、无证书 State、有证书 State；保持 Contract、当前工作集、模型及工具条件一致。注入早期约束、用户更正、错误假设、失败路径和后续反证。按独立预设答案测下一行动是否正确，不能只看与原 Agent 是否一致，因为原 Agent 也可能错。
5. **有独立收益后才接一处循环边界。** 先明确 I2/I8、单写者和覆盖集，测试崩溃/过期版本/缺失引用/漏吸收分支，再扩到其他节点。工具节点的真实对照需受账本管理的 scratch run，这是明确扩张，不能宣称当前无工具 harness 已支持。
6. **跨 run 优化留在离线实验。** 优先复用 MIPRO/GEPA 类候选提议与验证思路，比较条件化经验和无经验；未证明收益前，不增加在线 optimizer 服务或全局经验自动投影。[R8、R10]

接管实验同时测约束违规、错误重试、召回遗漏、下一行动、Update 拒绝率、调用延迟和总输入/输出 token。10–20 次压缩用于暴露累积语义错误；50–100 次状态更新可检查增长趋势，但合成机械测试不能代替真实模型质量实验。这些是实验规模，不是生产任务的隐式终止限制。

关于噪声，§2.7 的正确收窄是：**一个确定性坏例足以证明缺陷存在；一个修复后的好例不足以证明可靠修复或普遍收益。** 不必为字段相等做统计，但语义收益和失败概率仍需重复及独立任务。

### F2. 最不该做的事

- 因为有早期 schema，就把完整第 2 层列为所有改进的前置依赖。
- 同时建设认知库、知识图谱、向量库、归因服务和自修改观察者；这些均是扩张，当前没有足够实验依据。
- 让节点级观察者每次都重写全局状态，或者让经验绕过 I8 自动注入所有节点。
- 为了制造 plateau 固定截断事实，也不能反过来拒绝面对真实窗口容量。
- 把录制回放、JSON/schema 合法、引用可解析、局部检查通过，任意一项当作新策略正确的充分证据。
- 将通用“少于 major 即批准”经验覆盖领域验收，或让优化器通过修改边契约间接放宽质量门槛。

## G. 不同意的具体条目

| 位置 | 不同意的条目 | 理由或必须改成的限定 |
| --- | --- | --- |
| §1.2 证据一 | “60% 是字面重复” | 60% 的计算包含独有 verified 元数据。已核实的三字段去重是 34.92%，见 A1。 |
| §1.2 开头、证据二/六 | 全节来自同一真实运行；每轮缓存 99.9% | 缓存数来自事后重跑；6/6/4 minor 来自另一个 run，见 A2。 |
| §1.3 | 摘要天然不可测、不可审计 | 存储输入/输出、摘要版本和行为实验同样可测；是否为散文不决定能否审计。pi-smart-compact 已给出覆盖验证与可追踪修复先例。[R5] |
| §1.3 | 四者都只管历史，没有一者管当前需要什么 | SoL-Pi 的观察结果外置/分页与 smart recall 已反证这种排除；外部按步选择也有直接先例，见 B3。[R1–R5] |
| §1.3 | OpenAI compaction 等于整段历史清除重写 | 必须区分 SDK 的底层 session 替换操作和压缩输出的语义。官方指南说明返回窗口可含保留条目，API 参考还列出用户消息及 compaction item；不能推成所有内容均被模型重写。流式阻塞也须限定具体 SDK 调用路径，不能泛化到所有服务端压缩。[R15] |
| §2.1、§3.3、§4.5 | State 作为充分统计量能按构造解决历史爆炸 | 这是待检验的行为充分性目标，不是 schema 性质。Active、Index 和 Update 成本都可能增长；旧项目原文明确说不是语义等价证明。 |
| §2.2 | 休眠知识是引用，所以不会膨胀上下文 | 单个引用小不代表引用集合有界；未被索引或线索过弱的材料即使可寻址也可能永远想不到召回。 |
| §2.3、§4.5 | 因果式表达对近因免疫，能治被现象带偏 | 条件句可以编造因果，还可能固化错误抑制重试。必须用干预与接管实验验证；§4.4 自己承认并非可检查的因果结构。 |
| §2.5、§3.2 | frontier 可直接按循环边界移入图 | 单流前缀与分支证据覆盖不同；还遗漏单个节点工具循环内的长上下文。 |
| §2.6、§4.5 | 证书消除静默丢失，并保证更正/失败语义 | 能保证的首先是已登记 item 的处置覆盖；Episode 中从未纳入的关键内容不在旧 item 覆盖集。旧实现的 current_directive、accepted_next_action、next_plan 等也不在 reducer 的 item ledger 中；语义正确更不能由合法 source 前缀推出。 |
| §2.7 | “老道=参数变好；失忆=参数没变”，记忆不是老道载体 | 把训练权重、系统提示、可复用技能和非参数经验混成参数；若将记忆也定义为参数则成同义反复。反馈驱动的技能/经验更新已有行为迁移先例。[R11–R13] |
| §2.7 | 神经网络没有 per-node loss 这一优势 | 深度监督已在中间隐藏层设置辅助目标；中间监督不是图 Agent 独有。是否存在有效局部目标，与能否识别唯一因果责任仍是两件事。[R14] |
| §2.7、附录 B | 噪声只对边际改进成立 | 发现明显缺陷不需统计；证明修复可靠、比较泛化和解释归因仍受随机性影响。两者不可混同。 |
| §3.1 | 写图已完成目标谈判，图省掉状态不确定性来源 | 形式上发布图不证明验收与用户目标一致；§1.2 的错误交付契约恰是反例。运行输入也可能缺项或冲突。 |
| §3.2 | 直线 DAG 天然无漂移 | 无循环只能避免循环累积；上游有损转述、错误假设和节点内压缩仍会让后续节点偏离目标。 |
| §3.3、§4.3 | 没有宿主/投影层就是重复成因 | 已有声明式选择和共享 prompt 组装。直接机制是重复映射；不新建认知层即可去掉已证实冗余，见 B1。 |
| §3.4 | 内容不该泛化，经验应该泛化且趋于饱和 | 内容可以跨任务复用；程序性规则也可能高度环境特定。增长率与适用性是经验问题，不由字段类别决定。 |
| §3.5 | 真正老道必须自动投影经验，而可检索只是图书馆 | 自动选择与无条件投影是不同机制；检索到经验证的程序/规则同样能改变默认行为。[R12–R13] |
| §3.6 | 跨 run 拒绝向量检索就是错 | 不知道需要什么只证明需要发现机制，不证明必须向量化；结构化路由与 FTS 是可比较的基线。旧项目原文是“无需，直到召回失败证明必要”，不是永远禁止。[R5] |
| §3.6、§4.3 | 没有归因就只是观点；归因还是空的 | 应把解释假设、因果验证和优化信用分配分开；已有多模块优化，不必等待通用根因解法。[R7–R10] |
| §3.7 | 路子不对只能停下找人 | 固定图未预留替代路径时成立；如果图已声明条件分支或节点内部策略选择，run 内可以合法换路线。仍应坚持 I1，而非将其说成普遍计算限制。 |
| §3.8 | 同一 Update 协议能承载三个尺度；测试台裁决 | 可以复用提案/提交框架，不能复用信任标准。当前 harness 明确不判断质量，只产生结果；裁决依赖独立评价与适用域。 |
| §3.8 | 新观察者就是 Fresh-Agent Takeover | takeover 测状态是否足够继续；独立审计者测失败解释。任务和真值标准不同，陌生观察者也可能共享模型偏差。 |
| §3.8 | 允许改边契约，又不允许改“怎么算合格” | 边契约可能规定必须提供/保留的证据，本身就在定义局部合格。必须按语义影响分权限，而非仅按字段名。 |
| §4.2–4.3 | 归因属于状态核心；第 2 层照设计做即可 | 边界互相矛盾，且 I2、I8、图 frontier 与更新所有权尚未接好，见 D。 |
| §4.4 | 无通用关系系统就不能表达依赖；二值置信度必然太粗 | 散文可表达依赖，只是不能机械查询/失效传播；是否需要通用关系或数值置信度应由具体失效证明，模型自报数值不自动更可信。 |
| §4.7 | 先建第 2 层即可解决工作集没有归宿 | 与 §3.3、附录 C“状态不解决工作集”直接冲突，也被现有最小去重实验削弱。应改为先验证输入选择和认知连续性两个独立问题。 |

另对简报 §4 的提醒提出异议：“验证覆盖面/证据纪律”不是与 RAG 相反的立场。召回决定如何取得材料，验证决定哪些断言可被接受，两者是正交职责。把它们对立，会使相关工作筛选偏离真正的比较维度。

## 最后判断

**应该先证明：在同样的输入选择和工作集条件下，可问责 State 比结构化摘要更能保持正确行动。**

在此之前，修复反馈映射是明确工程任务；认知连续性是待测假设；跨 run 优化是已有先例可借鉴的离线研究。把三者捆成一个先建的内核，是本方案目前最可能的失败方式。
