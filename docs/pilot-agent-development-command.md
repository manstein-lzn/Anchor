# Anchor Pilot 当前目标开发命令

工作目录：`/root/Anchor`

## 开始前

完整阅读：

- `AGENTS.md`
- `docs/pilot-development-plan.md`
- `docs/architecture.md`
- `docs/product-architecture.md`

以开发台账的“当前目标开发”范围为准，完成实现与验证。

## 开发范围

1. 接入 PydanticAI / Harness 原生持久记录，保留 JSONL、消息快照及相关文件。
2. 用户重新打开同一 Session 后，可以发送新消息；Agent 加载中断历史、查询现场并继续工作。
3. 收敛阻断正常续聊的旧门禁，取消已授权普通操作的重复审批；保留必要提问、权限校验和沙箱边界。
4. 长对话需要压缩时，使用 Harness 已有接口。
5. 聊天中的 Graph、Run、Artifact 引用可以直接跳转已有页面，并能返回原会话。
6. 完成真实 provider、浏览器和进程中断后的续聊验收。

## 实现约束

- 先查本地固定版本框架 API 和仓库已有调用，再做最小接入。
- 不自研日志格式、JSONL 解析器、恢复引擎、记忆系统、计划系统或审批平台。
- 已有必要提问可继续复用，不为更换接口重写已可用功能。
- 如果框架确实存在缺口，先说明复现场景、替代方案和最小自研范围，得到用户明确同意后再实现。
- 系统 Pilot、计划展示、研究合同、附件、分支和导出仅为后续产品需求，本轮不开发。
- 保留现有会话和工作区改动，不清理历史，不覆盖无关修改，不自动提交无关文件。
- `src/anchor/serve.py` 不得在模块级导入 `pydantic_ai`。

## 必须验证

使用独立测试数据和服务实例，避免中断用户正在运行的任务。

- 正常对话、工具调用、刷新、断线重连和停止仍可用。
- 模型输出中途终止服务进程，重新启动后，同一 Session 能带新输入继续。
- 工具结果已经保存时，重启后 Agent 能读取该结果。
- 工具结果缺失时，如实保留中断事实，Agent 能查询现场后继续，不要求用户处理操作账本，也不盲目重放旧操作。
- 必要提问后，用户回答能回到原会话。
- Graph、Run、Artifact 跳转及返回会话实际可用。
- 如启用压缩，验证真实长会话；未验证的能力必须明确标注。

开发中只跑相关测试；阶段完成后运行：

```bash
./.venv/bin/python -m pytest -q -n 8 --dist worksteal
npm --prefix apps/web test
npm --prefix apps/web run test:e2e
npm --prefix apps/web run build
```

模拟测试不能代替真实 provider 和浏览器验收；旧审批测试不能算作新续聊目标通过。

## 交付要求

每完成一步，更新 `docs/pilot-development-plan.md` 的推进记录和对应验收项。

最终报告必须包含：

- 改动文件及解决的问题；
- 测试命令、退出结果；
- 真实验收的复现步骤、Session/Run 标识及证据路径；
- 尚未完成或未经验证的项目。

保留测试记录供独立验收，不在报告中暴露密钥。完成当前范围后停止，不自动扩展后续需求。
