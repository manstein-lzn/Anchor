## 1. 目标与非目标

证明 PydanticAI Harness 能在 Anchor 单 bash 节点中限制模型上下文，保留任务必要信息及完整执行证据，并能在真实任务上评估压缩造成的信息损失。

复用 01 的 Node 入口、真实沙箱和立即完成语义。固定 PydanticAI 2.46.0、Harness 0.32.0，版本变化须报告并重新验证契约。

不实现 crash resume、WAITING、前端、Graph 迁移、通用 shell 解析器、自动知识库或工具注册平台。不要同时启用全部压缩策略。不要自行重写 token 估算和摘要算法以证明框架“能用”。

## 2. 所有权与接入

建议独立分支 `research/node-context`，从 G1 验收 SHA 建立。拥有一个最小上下文策略模块、独立测试和实验说明；具体路径由 G1 填定。共享 Node 入口、公共结果 schema、依赖文件、trace 写入器与执行桥由主集成拥有，变更需求通过小 patch 建议交回，不在包内复制。

通过 G1 的 capability 组合接缝接入。02 负责模型所见历史的处理和大输出可读引用；03 负责快照持久化和恢复选择。两包不能共同修改一份“current messages”持久文件。

## 3. 最小实现

### 上下文策略

- 使用 Harness 已提供的策略，先选一个确定性压缩策略和一个摘要策略；证明最小组合足够后再决定是否需要 Tiered。
- 预算用显式配置，记录真实模型窗口、输出预留、输入目标和估算方式。测试通过小预算触发，不以硬编码 80% 当作正确性证明。
- 保留公共规则、任务约束、近期交互与工具消息结构。pin 仅放确实不能丢失的小段任务约束；不要另造由模型维护的大型 durable state schema。
- 单条超大消息、不可再压缩的 pinned 内容或模型响应都可能使目标无法达到。此时有限地失败并说明原因，不能无限摘要或继续发送明显超预算请求。
- 不启用需要自行识别任意 bash 文件读取的 DeduplicateFileReads。不能为了去重而猜测 shell 语义。

### 大输出与单 bash

模型可见工具仍只有 bash。不要启用会额外注册 `read_tool_result` 的默认 spill 模式。

优先检查 Harness 是否提供可复用且不增加工具的输出存储接缝；不存在时，用最小文件存储与 bash 读取路径解决。允许使用原生命令 `head`、`sed`、`tail`，不强制新增 CLI。

必须在沙箱现有截断发生前保存输出才能声称无损。若为此必须修改共享执行层，提交具体小 patch 给主集成；不能把已经截断的 1 MB 字符串落盘后称作完整结果。设有限存储上限，超过上限显式报错或标记截断，不能无限占用内存/磁盘。

存储位置、沙箱只读访问路径由主集成确认：不混入节点业务产物、不允许 Agent 修改内部记录、不暴露宿主机任意文件。仅提供本次执行所需输出；此包执行期间保留，清理暂为显式操作，不能提前删掉 03 可能恢复引用的文件。

### 完整记录与有限上下文

保留所有模型响应和工具结果/完整输出引用的追加记录；压缩只作用于模型输入。记录每次处理前后数量、估算 token、策略及摘要调用用量。不得通过改写原始 trace 来“节省上下文”。

不在本包声称这些记录能够 crash resume。将私有历史序列化方式和输出引用格式交给 03 与主集成评估。

### Provider 超限

用模拟 provider 异常验证实际框架行为。若有可可靠识别的窗口超限错误且公开 API 支持强制压缩，可做最多一次压缩重试；否则清晰失败并报告限制。禁止捕获所有异常统一当作窗口超限，禁止因此重新执行工具。无需为了“通过”自造一套通用供应商错误分类。

## 4. 自动验收

| ID | 场景 | 必须验证 |
| --- | --- | --- |
| B1 | 多轮超过小预算 | 实际模型请求输入受到控制；压缩确实触发；不是只打印历史长度 |
| B2 | 工具配对 | 对模型实际收到的每次历史验证调用 ID/返回结构，无孤立返回或错误跨轮关联 |
| B3 | 大输出末尾标记 | 输出超过沙箱原有限额，末尾含唯一标记；首次模型观察有界，随后可通过真实 bash 找回标记；记录哈希/长度匹配 |
| B4 | 单 bash 与权限 | 工具集合始终恰为 bash；输出可读但检查点/审计记录不可写；结果文件不是 Graph 业务产物 |
| B5 | 早期约束 | 构造早期任务约束，在多次处理后检查模型输入仍具备必要约束；确定性摘要只能证明接线正确 |
| B6 | 原始记录 | 模型上下文被压缩后，原始消息和结果引用仍完整；重复运行不串数据 |
| B7 | 无法压缩 | pinned 内容自身超预算、摘要失败、异常大消息时有限结束，状态明确，无无限重试 |
| B8 | 超限模拟 | provider 拒绝后按声明策略有限恢复或失败；不重复工具副作用；非窗口错误不误判 |
| B9 | 完成与请求计数 | 接受提交后不再压缩/请求模型；摘要调用与主模型调用分别记录，预算口径明确 |
| B10 | 容量上限 | 输出文件达到配置限额时可辨认；无静默“完整”声明；存储失败不伪装成功 |

使用现有确定性模型与真实沙箱，测试只替换模型。覆盖 01 的立即提交与串行调用回归。只要必要测试 skip，就报告部分完成，不宣称全通过。

## 5. 小规模真实模型实验

真实实验需要可用且获授权的模型端点、预算和已知窗口。沿用项目已配置的授权资源；无资源时提交可运行命令和待验证项，不能读取或输出凭证，也不要擅自选择付费服务。

初期三个小任务，每个重复两次即可：多文件任务约束保留、分段证据整合、读取长输出后定位末尾信息。模型采用项目实际目标模型，摘要模型与配置明确记录。验收条件在运行前写定，包括业务产物、早期约束、引用准确性和不允许出现的行为。

对同样输入运行 mini 基线和 Pydantic 候选；控制总任务预算并报告摘要额外调用，不强求两者内部 token 完全相等。保存实际输入大小、成功/失败、约束丢失、调用数、可取得的 token/费用和用时。失败样本不得删除或反复挑选最好一次。

这六次/每候选的实验只是迁移信号，不证明稳定性。真实 provider 窗口拒绝测试若费用或端点条件不允许，标为未验证；模拟异常不等于真实 provider 已通过。
