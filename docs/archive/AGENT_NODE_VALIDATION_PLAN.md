> 文中的“下一步”“待实施”“必须”及旧阅读顺序仅适用于当时阶段，不作为后续开发指令。
> 当前入口见 [项目 README](../../README.md)，唯一升级方向见 [Plugin 设计](../plugins.md)。

这是三份实施计划的调度说明，不是正式迁移决定。第一包已通过主验收；第二、三包现在可从下述 G1 基线分别实施，共享文件修改仍由主集成收敛。

## 依赖关系

```text
01 最小 Node 适配与控制流
             ↓
G1 主验收：重跑测试，冻结入口和组合接缝
             ↓
     ┌───────┴────────┐
02 上下文验证       03 持久化与崩溃验证
     └───────┬────────┘
             ↓
G2 主验收：组合两包，验证压缩后的恢复
             ↓
评估是否正式迁移；另立实施范围与 ADR
```

02 与 03 职责分离，但不是完全正交：它们共同接触消息历史、执行记录和框架生命周期。各自通过不等于组合正确，G2 不得省略。

| 包 | 责任与拥有状态 | 输入 / 交付 | 预估工作占比 | 依赖与独立验证 |
| --- | --- | --- | ---: | --- |
| 01 | Node 调用、bash 执行、完成边界 | 当前代码 → 最小入口与真实图测试 | 30% | 先实施；确定性模型 + 真实沙箱 |
| 02 | 模型上下文预算、压缩、大输出引用 | G1 入口 → 上下文策略模块及效果证据 | 25% | 等 G1；不依赖 03 的恢复实现 |
| 03 | 持久化、恢复判定、副作用状态 | G1 入口 → 本地持久化和故障实验 | 30% | 等 G1；不依赖 02 的压缩实现 |
| 主集成 | 共享契约、记录组合、验收与最终判断 | 各包 commit → 可复验综合结论 | 15% | G1、G2 与真实模型证据检查 |

占比仅用于分工，不是工期承诺。03 的风险集中在崩溃窗口，不能用普通成功路径测试抵消。02 的真实摘要效果依赖实际模型，不能用替身结果冒充。

## G1：允许并行之前必须冻结

状态：**G1 已通过**。基线 `b9aae105d2ab0beb24afa93272a9d0186e4aa70f`；独立复验 145 项后端测试、ruff、mypy 通过。详见 `AGENT_NODE_PLAN_01_ACCEPTANCE.md`。

冻结边界与文件归属：

- 公共请求/结果：`src/anchor/node/__init__.py` 的 NodeRequest / NodeOutcome，由主集成管理。
- 执行与 capability 接缝：`src/anchor/node/pydantic_adapter.py` 的 `run_node(request, *, model, capabilities=())`、`build_agent`，由主集成管理。model/capabilities 为适配器构造依赖，不加入公共请求类型。
- 真实执行层：`src/anchor/runtime/execenv.py` 的 NodeSandbox，由主集成管理。第二包如需截断前保存输出，提交该层的小 patch 建议，不复制沙箱。
- 共同夹具/回归：`tests/test_node_controlflow.py`，由主集成管理；model_from 按历史 response 数选脚本，压缩删除历史时不可直接当作稳定计数器，第二包自行建立独立计数的测试模型。
- 第二包拥有 `src/anchor/node/context.py`（需要时新增）、`tests/test_node_context.py` 及独立实验；第三包拥有 `src/anchor/node/recovery.py`（需要时新增）、`tests/test_node_recovery.py` 及故障实验。允许各包内部合理拆文件，不同时改公共适配器。
- 依赖文件、trace 写入器、图集成桥、默认 mini 路径归主集成。包内通过已有 capabilities 参数组合，缺失的共享接缝以 patch 建议交回。
- 当前 trace 在结束时写出；末批结果来自已形成的 ModelRequestNode.request。它不是流式审计、不可变事件存储或 crash checkpoint。
- **第三包必须先验证**：Node completed 对应框架 CancelledError，run-level 完成钩子不能被假定已成功执行。终态持久化适配在第三包范围内；失败应形成不迁移证据，而不是回放提交命令。
- **第二包必须处理**：capability 改写后的 all_messages 不能充当完整原始记录；工具输出与模型上下文需要分开保留。

1. 执行入口、请求/结果、正常终止和错误映射。
2. 组装框架 capability 的实际位置；工具执行生命周期、模型历史读取方式。只暴露本次验证需要的接缝，不预建插件总线。
3. 完整记录、模型上下文与工具输出引用的所有权。02 可以改模型历史，不能改写完整记录；03 可以持久化快照，不能擅自改压缩策略。
4. 共享测试夹具：真实沙箱、确定性模型、立即完成、步骤观察点。
5. 共享文件清单与修改归属。现有适配器、公共契约、依赖文件和图集成桥由主集成负责；两包通过独立模块及自己的测试接入。

若不修改同一适配器文件就无法开发两包，先由主集成补一个最小组合接缝；若接缝仍不稳定，顺序执行 02、03，不以并行为目标增加抽象。

后续 Agent 现在可以阅读文档、核查候选 API、准备测试数据。不得基于猜测的 Node API 开发生产适配，更不能从 01 未验收的工作区复制一份入口各自演化。

## G2：组合验收由主集成负责

具体执行与交付要求见 `AGENT_NODE_PLAN_G2.md`。第三包原验收结论需收窄：实际继续执行、写入间隙、重复恢复和真实累计预算尚需补验，先满足该计划的 A 门槛，再作组合通过判断。

从同一 G1 基线接收两包独立 commit，先检查契约和所有权，再组合；修复归属包内的问题交回对应实施方。

必须在同一 Node 实例中同时启用上下文策略与持久化，检查：

- 压缩后重启，实际传给模型的是正确的有限上下文，而非恢复为未经压缩的全部历史。
- 完整原始记录仍可追溯；快照、摘要、历史版本和工具结果引用关联正确。
- 大输出引用在重启后仍能通过 bash 读取；模型不能修改内部检查点与审计记录。
- 在压缩前、压缩持久化后、工具副作用后记录前中断；恢复不丢关键约束、不重复已确认副作用、不隐藏未知状态。
- 累计预算不会因重启或重新摘要无故清零；终止和多工具顺序仍满足 01。
- 真实 Agent→op→Agent 图闭环以及 mini 默认路径回归继续通过。

真实模型实验与故障注入分开记录。没有真实模型条件可以完成结构性验收，但最终结论必须保留“摘要质量未验证”。发生候选框架限制时允许得出不迁移结论。
