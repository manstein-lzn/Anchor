## 1. 决定

### D1 成本：每一次被裁决的提交都计费，与裁决结果无关

**缺陷**：`Kernel::adjudicate` 在局部副本上累加 `spent`，只有接受和预算耗尽两条路径把副本写回，打回、拒绝、版本过期时成本丢失。预算因此可以被无限次打回绕过。

**定律**：任务的已花费 = 其历史中所有记录的 `stamp.cost` 之和。凡是写进该任务历史的提交（接受、打回、拒绝、版本过期、待定），都计费。

**实现约束**：
- 成本**不得**推进资源版本。版本只表示"已接受的改变"；若打回也推进版本，并行分支会互相制造版本过期。
- 因此 `spent` 不能作为普通版本化状态写回。推荐做法：`Record` 携带写入后的累计已花费，加载时取最后一条记录的值；或从历史求和。二选一，在工作记录说明。
- 超出预算的那一次提交本身导致结算为失败（现有行为保留）。
- **重试契约（宿主侧）**：`cost` 是"自该提议者上一次提交以来新发生的花费"。版本过期后重新提交同一份工作时，宿主报告 `cost = 0`。必须有测试证明一次实际花费不会因重试被计费两次。
- 崩溃后宿主重放同一提交导致的重复计费，本次不处理，登记为已知未决项。

### D2 存储：历史只由完整行组成；只有最后一行可能残缺

**缺陷**：`FileStore::history` 遇到第一行解析失败就停止，追加在残缺行之后的完整记录全部不可见；`load` 的崩溃恢复依赖历史，于是已接受的事实在重启后丢失。

**定律**：
- `commit` 在追加前（在内核写锁内），若历史文件末尾不以换行结束，先截断到最后一个换行。被截掉的字节从未构成过记录，这不是改写历史。
- 读取时，只有**最后一行**允许残缺并被忽略；**非末行**无法解析是损坏，返回 `StoreError::Corrupt`，fail-closed，绝不静默跳过。
- 已存在的完整记录逐字节不变。

### D3 宿主阻塞：可信的宿主代码可以凭观察把任务交给人，但不能把它要回来

**缺陷**：宿主观察到未知外部效果时，没有任何合法方式让 Run 进入"等待人"。`stop` 只允许人。

**定律（不对称）**：阻塞是安全方向，释放不是。
- `stop`：人可以随时提交；宿主代码（`Code`）可以提交，但**必须附至少一条 `Evidence::Observation`**，原因写入 `Waiter::Human { reason }`；Agent 永远不可以。
- 释放人的等待仍然只有人可以（现有规则不变）。
- 不新增 `Waiter` 变体，不新增内核相位，不为 Graph 或 Goose 写专门分支。

### D4 中断：中断事实是宿主事实，只能由宿主代码提交（校验器扩展）

**缺陷**：`NodeSubmission` 没有 interruption，`record_result` 固定写 `None`，常驻助手的打断无法表达。

**决定**：修订原计划"节点失败结算是唯一允许的校验器扩展"，增加这一项：
- `NodeSubmission` 增加可选 `interruption`。
- 带 `interruption` 的提交只接受 `Code`；Agent 提交带中断字段一律拒绝（Agent 不能声称自己被打断）。
- 中断结果写入 `RunResult.interruption`，产物类型为中断控制产物，沿普通路由继续；suppressed 与投递账本语义由 Host 保留，不进校验器。

### D5 等待中的任务只接受生命周期请求（探针中标为"不阻塞"，审查改为必修）

**问题**：探针观察到，人停止 Run 之后，宿主代码迟到的节点结果仍被接受，Graph 在停止状态下继续推进。预检建议由调度器丢弃迟到结果。

**否决该建议的理由**：那是靠调度器自觉遵守的软规则，正是宪法要避免的形态。C4 要求"停止就是一次提交"，停止被接受之后就不应再有任何写入能推进这个任务。

**定律**：任务处于 `Waiting` 时，只接受 `Action::Request` 的生命周期控制；其他一切提交（任何身份）以 `TaskWaiting` 拒绝，并照常记录与计费（D1）。

**已核对不影响现有流程**：Op.call 的顺序是"绑定 → 等待子任务 → 宿主 resume → 提交完成"，等待期间宿主不写空位；人对待定变更的批准作用于 `pending/*` 资源，不经过被等待的任务。差分测试会验证这一点。

## 2. 授权范围

| 允许 | 不允许 |

| `anchor-kernel` 中实现 D1、D2、D3、D5 | 内核新增依赖、新增 `Waiter` 或相位、任何 Graph/Host/Goose 专属分支 |

| 删除预检探针目录，或保留为回归，二选一并说明 | — |

## 3. 完成 K0.1 的检查（我验收时逐条核对）

1. 三个预检反例改写为 `anchor-kernel` 中的正式测试，修复前失败、修复后通过（提交中能看到测试先于或同于修复）。
2. D1：三次打回成本 6、预算 10 → 第二次提交即结算为预算耗尽；并发两分支一方版本过期后以 `cost = 0` 重提，总花费只计一次。
3. D2：残缺尾行 → 追加 → 读到全部完整记录；残缺尾行 → 追加 → 丢失状态写入 → 重启 → 恢复已接受事实；非末行损坏 → `Corrupt`；既有完整行逐字节不变。
4. D3：`Code` 无观察证据的 `stop` 被拒；有证据被接受；`Code` 不能 `resume` 人的等待；Agent 的 `stop` 被拒。
5. D4：Agent 带中断字段被拒；Code 带中断字段被接受并写入 `RunResult.interruption`。
6. D5：等待中，任何身份的空位写入被拒且计费；Op.call 流程不受影响。
7. 三组差分测试（20,000 例）全部通过，断言未放宽。
8. `git diff 35ac2b1 -- rust/anchor-kernel/Cargo.toml` 为空（依赖不变）。
9. 工作记录登记 S10 起的语义变更：至少包括 D1（打回计费）、D5（等待中拒绝写入）。

K0.1 单独提交，通过检查后再开始 H1。
