归档于 2026-11-13：S0-S6 的实现与本地确定性联合验收已收口，正文保留当时目标和门槛，不继续充当待办。真实 Provider、生产影子/切换、完整当前发行安装和持续净收益未由本轮验证；S7、性能与暴露映射边界归[当前台账](../../pilot-development-plan.md#正在收口)，当前契约见[数据中枢](../../harness-data-hub.md)，实际结果见[联合验收](../../../experiments/harness-hub-v3/README.md)。

本文是基于 2026-11-13 审计制定的待实施方案，不是当前实现契约，也不表示已修复或已获准部署。当前行为归[数据中枢契约](../../harness-data-hub.md)和[架构](../../architecture.md#dreaming-基础接入)；完成状态、未关闭项和证据只维护在[统一台账](../../pilot-development-plan.md#正在收口)。各切片验收后更新当前契约，全部完成后本文退出活跃入口。

## 1. 交付目标与范围

把现有中枢从“能记录、能调查”完善为可信的全局分析底座：**相同 Harness 可以积累样本，不同来源不混算，质量缺失明确，结论与证据强度相称，并能用后续运行检验变化。** 发现仍由结构化分析驱动，不要求模型逐个阅读 Graph/Run 历史。

本轮完整交付包括 S0-S6：

- 修复五项审计问题：配置碎片化、质量缺失未披露、跨来源碰撞、工具恢复/重复归因过强、热投影保留已删除资源。
- 让 Dreaming 在明确授权内关联安全的 Run/Grade 投影，区分执行结局、独立质量与费用/时间完整性。
- 实现最小可用的跨周期关联及前后统计，处理迟到评分、跨周期运行、重新评分与重复读取。
- 通过真实 Host/Runner/Goose ACP/MCP 的确定性闭环及 10k Graph 事实基准，验证正确性、权限和物理成本。

本轮不引入强化学习、另一套 Agent loop、数据仓库、发布器、人工逐提案审批或默认模型预算。Hub 不取得写事实、评分或发布权；现有独立实验/留出/gate/submit Apply/Withdraw 路径继续作为自动改进的唯一裁决与落地路径。生产趋势用于发现与后验监测，不替代受控实验的因果证据。

“Anchor 级”指分析可按 Graph、Plugin、模型、工具、Host、运行环境等维度定位问题，不表示 Dreaming 获得修改 Anchor/Goose 二进制的能力。Pilot/Op 与调用中途崩溃的采集缺口另列 S7；完成本轮不得表述为所有 Agent 路径已全面可观测。

## 3. 不变的所有权与最小替代

| 所有者 | 本轮责任 | 不做什么 |
| --- | --- | --- |
| `anchor-facts` | 共享身份、版本、结构化投影与冻结查询的纯类型/校验/摘要 | 不读环境、磁盘、Run 业务状态，不执行分析 |
| Runtime + Host 记录侧 | 用已冻结的执行请求记录正确配置与请求上下文身份 | 不改变 prompt、恢复选择、工具许可或 Goose loop |
| `application/run_access` | 从权威 Run 事实导出安全的结构投影，沿用既有访问与并发边界 | 不让 Dreaming 直接读 `kernel-runs` 或返回业务正文 |
| Eval/评分所有者 | 保持独立 Grade 写入和来源身份，提供允许发现的评分事实 | 不把 grader 权限交给 Agent 或 Host 记录器 |
| Hub L0-L4 | 来源关联、可重建投影、纯查询/分析、只读协议 | 不增加写数据根路径，不依赖 Host/Runtime crate |
| Dreaming Host | 冻结授权、视图、上下文和证据引用，复用既有周期/Artifact/回收 | 不新建分析权威库、周期队列或审批流程 |

新增机制必须替代现有缺陷路径，而不是并排维护：

- 稳定配置摘要替代包含任务输入的配置分组；请求摘要放观察中，不再为每个输入创建一份稳定配置。
- 带安装域的关联键替代仅 Run ID 的关联；所有分析器/MCP 共用，不各自补前缀。
- 一套来源撤除/失效逻辑替代只追加的热投影；不靠定时重启掩盖错误。
- 明确的弱线索替代未经证实的 `call_corrected`/重试解释；不并列保留旧强结论。
- 受授权的安全视图替代 Dreaming 只能看观察根的接入限制；不再开放一条 raw Run/Goose 旁路。
- 冻结历史关联查询替代“待办累积就是长期分析”的假设；不把统计结果升格为新的事实权威。

## 4. 目标契约

以下均为待实施选择。序列化形状、权限和切换点在相应切片前固定成正反例，不能边部署边猜。

### 4.1 稳定配置与请求上下文

继续使用 `AgentConfiguration.digest()` 作为稳定配置身份，不另存一套可漂移的 `harness_digest`。

1. 新配置身份语义单独版本化，目标为配置 v2；不要为了配置字段的变化整体抬高 Observation/Grade 的版本。
2. `instructions_sha256` 只绑定静态角色指导。Graph 的 objective、节点静态指令等由既有 `graph_digest` 绑定；实际指导版本仍由冻结 envelope 绑定。模型绑定、Goose/Host、工具定义、Plugin 内容/授权、路由及沙箱环境继续进入配置。
3. 参数输入、上游产物、Run/Workspace 路径和临时消息不进入稳定配置。不能从格式化的 `request.task` 中解析并删除 `Input:`，应从现有结构化来源计算。
4. 每次模型 attempt 的观察另带当前请求上下文摘要，绑定本次 task/input 与已选指导；不声称它覆盖 Goose 持有的整个原生会话，更不复制聊天或隐藏推理。摘要也不是匿名化保证，仍受事实权限限制。
5. 本轮先验证现有 envelope 不含易变输入路径；不能把新的碎片化源留在其他字段。Plugin 动态业务数据不混进 Plugin 版本身份。
6. v1 的复合摘要无法安全拆回静态指导与输入，不改写旧配置/Record，也不通过省略旧 instructions 字段将不同指导粗暴合并。旧数据仍可用于有效的用量/失败观察，稳定配置比较标记为旧身份不可归并，与 v2 分开。

跨 Graph 的结构性信号可以聚合；成本/质量优劣比较必须另满足任务、评分器与输入群体可比性，不能为了扩大样本把不同任务放进同一个均值。

### 4.2 来源身份与关联域

区分三个不同概念：

| 概念 | 作用 |
| --- | --- |
| `source_instance` + 物理指纹 | 标识某一来源根，验证授权、替换和冻结引用 |
| 安装级关联域（建议 DTO 名 `join_namespace`） | 明确哪些 Run/trace/Grade 属于同一安装，可以按自然 ID 关联 |
| `{root, resource, place}` / `FactRef` | 精确引用某根中的某条历史，不因聚合而重写 |

目标 Run 键为 `(namespace, run_id)`，invocation 键在其上增加 node/invocation；同一安装的 Run、观察与评分分处不同根，必须仍能正确 join，不能简单把根路径加进键就结束。

- Host 从已登记的安装状态目录身份派生 opaque 关联域并绑定各来源，不新增持久安装 ID 服务。物理目录被替换时不得沿用旧游标/窗口。
- 普通 CLI 对明确 Host state 布局的同一父目录下已知根可以建立关联域；任意独立根默认隔离。非标准布局通过显式类型化映射声明关联，不用相似名字、路径包含关系或相同 Run ID 猜归属。
- 关联域是读侧关系声明，不是授权或评分可信证明。不同路径的备份默认隔离；显式合并/去重须有准确来源关系，不能静默双计。
- 同域同 invocation 的 Graph 身份冲突应报数据冲突，不取第一条配置、也不伪装两个合法 attempt。
- 评分只在同域同 Run、同 task/version/评分器语义内选同一权威历史的最新 accepted 位置。多个评分根冲突应保留并报告；不按根遍历顺序取最后一份，不把跨根时间戳当全局序号。
- 批量排除、ordinary 抽样、details、profile/contrast/front 和 MCP 查询都使用同一关联键。裸 Run ID 在多域下有歧义时要求显式范围，不“随便选一个”。

### 4.3 热投影的生命周期

正常刷新必须得到与同一现场冷重建一致的可见事实集。

- 一次成功枚举后撤除确已不存在的资源及其历史行、来源引用、评分和可选调用明细；共享内容寻址配置按有效来源引用保留，不能因删一个来源误删其他合法来源。
- 撤除整根时同步清理 `opened`、读游标和投影；失败的打开不能永久被记为已成功登记。
- 枚举/读取错误不等于“根为空”。未完成刷新不发布一份自称完整的混合视图；保留旧投影时标明 stale/error，相关统计不可当作当前健康结果。
- 同名资源删除后重建、文件实例替换或截断，清除旧读取位置再重建；不把旧历史位置套在新资源上，也不改写权威存储来修读缓存。
- 冻结窗口不因此重写历史：追加不漂移；原前缀已删除/改变则重放明确失败。新分析域的重新建基不伪装旧窗口连续推进，沿用既有引用保护，不增加默认保留期限。

### 4.4 工具信号的证据强度

发现层保留事实和线索，但停止由工具形状推出因果。

| 已有证据 | 允许输出 | 不允许输出 |
| --- | --- | --- |
| 同工具先失败后成功 | 同工具后续成功的弱线索、次数、证据与归因未知 | 已纠正、原失败已解决 |
| 连续同工具/形状失败 | 同形状失败序列，明确可能是不同操作 | 同一命令重试、陷入循环 |
| 同一 request 的并行调用 | 同批次事实，不猜执行依赖 | 将列表先后当成模型观察结果后的修复 |
| `program`、路径类别、typed CommandEnd | 程序/错误族分组与命令真实结局 | 用 shell 启发式替代原程序名，或工具成功等于退出零 |

本轮先改弱结论，不为了维持旧标签而新增完整 argv、路径或参数值记录。将来若真实用例确需判定重试，再单独评估最小操作指纹及其隐私/版本契约；本轮不把它作为前置条件。新信号代码/版本必须同步修改 D0 提示、测试及旧待办解释，不能让消费方继续把弱线索读成已证修复。

### 4.5 质量覆盖与安全投影

质量接入分两步，不能等所有业务都有评分才披露缺口。

**先输出能力与覆盖。** 保留 `not_applicable`，并增加按分析功能说明的数据状态：未授权、来源缺失、暂不可读、范围内无记录、已接入但无匹配评分、部分覆盖、冲突、可分析。至少分别报告：

- 获授权/可读的来源与声明范围；不泄露范围外资源数量。
- Run 生命周期、模型观察、独立 Grade 的可用性。
- 有结果但无观察、有观察但无 Run、应关联却缺 Grade 的数量；分母不明时为 unknown，不补零。
- 质量样本数、效率指标各自的完整样本数和排除原因。缺 token 不删除质量样本，缺 Grade 不把成功率当质量。

**再接入安全视图。** 推荐不把 `kernel-runs` 原始根直接交给 Hub 子进程，因为它的 Record/after 含业务输入、产物和 Graph 状态。

1. Run 所有者通过 `run_access` 导出最小白名单结构视图：Run/Graph 身份、相位与标准结局、已接纳节点槽位、时间/配置可用性、可信来源类别、准确事实引用；不含 input、result 正文、prompt、异常详情、完整 snapshot/after。
2. 评分视图只包括明确授权的 accepted Grade、task/version、check 结果、评分器配置与准确引用；写入仍归 Eval。它不向模型暴露评分器的期望数据或执行权限。
3. Run/Grade 投影视图经已有周期 Artifact 冻结，声明为可重建派生数据。Hub 从共享 DTO 读取而不链接 Host/Runtime；Host 对视图和响应作字段闭集、摘要、来源和范围校验。
4. 视图由各自所有者核对冻结位置；不存在跨根原子快照，暂时未关联项明确输出。新增数据和评分进入后续窗口，不能偷读当前根来补旧窗口。
5. 原始存储不复制出第二套 Run/Grade 权威，也不新建导出数据库。普通 Hub CLI 在用户明确授权原根时仍可走原 L0 读取路径；Dreaming 走安全视图，不自动继承 CLI 权限。
6. policy 中显式授予来源及视图类别。原 facts-only 策略不自动扩张；拒绝模型提供路径或自行添加来源。视图属于 Host Run 访问门面的一部分，依赖围栏不得放宽。

**保护评测与分母。** 生产、开发实验、留出、Dreaming 自测/meta 与 unknown 必须由宿主已有来源上下文标识，不能根据名字猜。留出逐项评分、用例身份及 case 级结果不得进入候选生成的普通发现接口；只消费现有受保护裁决允许的摘要。实验/自测不作为生产样本，不让自身生成的数据不断触发自调查。缺来源类别的旧数据单列，不能自动认定为生产。

即便登记了评分视图，也只表示“能分析已有独立评分”，不表示业务已普遍具备任务质量判定；业务评分口径仍由对应 Graph/评估包拥有，不造一个内容无关的万能质量分数。

### 4.6 跨周期关联与最小纵向分析

同一冻结查询区分两个范围：新增范围 `(after, through]` 决定新工作，获授权冻结前缀/历史区间提供关联与统计背景。两者都绑定 manifest、来源身份、策略范围和分析版本；支持范围不自动获得新的取证权限。

首版选择**从既有权威前缀/已冻结安全视图重建关联**，不先加持久聚合库。单次加载在内存中供多项分析复用；历史读取成本单列。只有实测超过既有传输/时限或资源门槛时，才另提一个可删可重建缓存的替代方案，不隐蔽增加第二权威。

- 跨窗关联：Run/观察在前、Grade 在后仍能 join；跨窗模型 attempt 仅计一次；重新评分更新该 Run 的当前评分视图，不把它变成一个新样本。每个旧版本的冻结结果仍可重放。
- 取证：历史支持项使用包含该项的准确冻结范围/manifest 引用。不得拿新窗口的 delta 键检查放行旧范围，也不得用“参与了聚合”作为原始内容访问许可。
- 时间契约：显式固定 `as_of`、基线区间和观察区间，采用 UTC 半开区间 `[start,end)`，界面按 Host 时区展示。使用何种宿主时间分桶须写入查询，缺时间单列，不编造跨资源因果顺序。
- 样本单位：Run 级结局/质量与 invocation 级效率分别计算；常驻 Run 的新输入 invocation 不能全部落到 Run 初次创建日，也不能把一个 Run Grade 复制成每个 invocation 的独立评分。
- 迟到事实：到达时间用于增量进度，原 Run/调用的已知时间用于所属统计区间。新报告可披露对旧区间的修订和截至时间；不能改写旧报告或把晚到评分误作新任务。
- 最小指标：任务/Graph 内的结局与独立质量覆盖、工具/命令错误族、完整 token/费用/Agent 时间的样本数与分布、同一稳定配置的前后变化。缺费用不报节省；尾部分布直接从样本计算，不平均各窗 p95。
- 可比性：按真实 task/version/评分器语义和生产类别分层；任务结构改变时报告组成变化。无可比标签时只作描述与结构性信号，不能跨 Graph 混合均值后宣称改善，避免任务构成变化造成反向结论。
- 后验监测：可按现有准确候选/部署配置身份关联生产暴露。仅按发布时间切前后不能证明属于某候选；运行时暴露未知则明确 unknown。发布与撤回仍消费原独立回执/策略，不让趋势报告自行生成 Execute。
- 新工作判定：旧问题仍存在但没有新证据，不重复唤醒模型；新 Grade、实质信号变化、待推进结果可以生成新工作。只做结构化对账不启动模型。现有 backlog 继续承载调查处置，不兼任统计数据库。

首版交付“冻结上下文下的前后对比与迟到关联”，不以此宣称完整序列挖掘、反事实重放或因果归因已实现。

### 4.7 协议、历史与切换

- 当前冻结协议 v2/Signals v3 与目标语义不能混写。本轮统一形成新协议代际，目标 window v3/Signals v4；安全视图、关联域、数据适用性和统计背景的字段闭集在发布前一起冻结，版本值不得冒充兼容证明。
- 序列化、manifest 摘要、分页、工具 schema、Host 校验、Hub/Eval 调用与发行握手同步更新。所有列表包括 front/坐标/时间桶都受分页或显式省略计数约束，不只约束信号表。
- 旧 Record、配置、manifest 和结果 Artifact 不改写；原始输入缺失的旧事实不补造稳定身份。新窗口从明确切换点建立分析基线，不伪装与旧分析语义连续。
- 活动旧窗口/待办仍需准确取证。保留最小只读旧格式适配，原分析结果读原不可变 Artifact，不用新 Signals 重算后冒称旧结果；需要重算的历史分析必须使用明确支持该版本的路径，否则返回版本不可用。
- 旧适配只有在活动周期、待办证据及 retained 引用均不再需要它，且原生回收允许后才能删除；不因本计划自动退休证据或清理数据。兼容分支在代码中写出这个删除条件。
- 共享摘要/键原语放中立词汇层，Host 与 Hub 不各写一份。新协议不能扩大已有模型权限，也不能改变独立 gate 对准确 assignment/GradeRef 的要求。

## 5. 开发切片与完成条件

### S7 后续采集覆盖，不混入本轮完成声明

对 Pilot、Op、调用中途崩溃/attempt 丢失建立明确覆盖矩阵，沿现有 Goose ACP、NodeExecutionPort、FactRecorder 和 Run 所有者补记录；先明确 attempt 身份、恢复成本和中断语义，再选择最小落盘点，不新造 Agent loop 或持续日志系统。此项不能只加一个“完整”布尔字段掩盖丢记录，也不能让观察失败转成任务失败。

S0-S6 可以先使已有数据的结论可信；S7 之后才能扩大“被覆盖执行路径”的声明。无法从现有事实重建的 host/sandbox 内部阶段继续列为 unknown，是否进一步细化须由真实信号驱动，不把所有内部函数都预埋成平台事件。

## 6. 验证矩阵与规模要求

| 层级 | 必须验证的行为 | 不能据此宣称 |
| --- | --- | --- |
| 纯类型与查询 | 配置摘要正反例；来源域；冲突评分；覆盖状态；时段/样本去重；固定输入输出 | 真实 Host 已正确记录 |
| 真实 Kernel fixture | 经 owner/Validator/submit 产生 Run/trace/Grade；删除重建；迟到与重新评分；非单调时间 | 业务模型质量变好 |
| Host + 固定 Goose + 确定性 Provider | 不同输入稳定分组；恢复保持冻结指导；安全视图；发现/实验/生产结果链 | 真实 Provider/渠道或长期收益已通过 |
| 授权与围栏 | Run 门面无新增例外；Hub 无写入/反向依赖；字段闭集；范围外哨兵、留出与原始内容不泄露 | 输出无业务值就等于分析进程未读过业务根 |
| 多周期/规模 fixture | 100/1k/10k Graph、多来源三类事实、多周期；重复/迟到/删除/冲突组合；分页遍历不漏不重 | 实际执行过 10k 个模型 Graph |
| 真实验收 | 经确认后的小范围 Provider 与只读生产对照，准确源码/二进制身份、费用、样本与失败记录 | 一次合格候选证明持续净收益 |

规模验收复用既有低频基准，不另建基准框架：

1. 固定信号与分页输入时，100/1k/10k 的首轮模型字段及条数保持同一约束；总数、未展示、缺口单列，继续保留普通中性抽样。
2. 增量读取路径无新增完整行时新增解析数为 0，追加 100/1 行不重新解析整段旧历史；新增的历史关联读取另外计量，不能混入“增量为零”的宣传口径。
3. 冷启动、热刷新、序列重建、安全视图导出、序列化与摘要分析分别测耗时/字节/解析数/峰值 RSS；fixture 生成的内存与 Hub 查询内存分开，Host 导出和子进程成本均不能漏记。
4. 在与现有基准同一机器/构建配置下先保存基线，再在运行新代码前固定对比口径；不得看到退化后修改数据或只报有利阶段。资源枚举和前缀重建允许随数据量增长，但不能虚称总 IO 为 O(新增)。
5. 超过已有 64 MiB 进程协议、256 KiB Agent 输出或 120 秒进程约束时显式失败/分页并说明原因，不截断后宣称完整。这些是传输边界，不新增任务预算。

验收产物同时给出同一组独立标注 fixture 的修复前/后对照：稳定配置组数、跨域误合并数、错误强归因数、热/冷不一致数、可匹配评分数、迟到事实重复计数，以及 Host/Hub/模型各自消耗。预期答案由 fixture 的 owner/独立评分定义，不由被测分析器自己的输出生成。正确性要求对应负例零混算、零强行归因、零越权和零重复样本；这只证明具名测试集，不估算未标注生产数据的准确率。结构化分析正确、模型输入有界和实际提出可采纳改善分别报告，不能只用通过测试数量证明基础设施价值。

每片先跑直接相关子集；跨模块语义完成后跑相应 crate 的完整测试与严格 Clippy/fmt、围栏。S6 跑必要 Rust 工作区回归及发行协议测试；改到 Web 投影才跑对应单测/构建/fixture 浏览器用例。命令、日志、源码/二进制身份进验收产物，当前契约只留结论与链接；本计划列的是未来门槛，不代表已经执行。

## 7. 架构确认点与上线边界

不为普通命名、模块拆分、错误映射或修 bug 逐项询问。以下涉及持久语义/权限/恢复，需要在实施到该边界前集中确认，不是每个 Dreaming 提案重新人审：

| 决策 | 本计划推荐方案 | 确认发生在哪一步 |
| --- | --- | --- |
| 配置与协议升级 | 新配置身份单独版本；请求摘要另记；旧事实不改写、不补造；窗口协议同步升级 | S2/S3 写入新格式及切换前 |
| Run/Grade 可见范围 | Host 经所有者导出白名单安全视图；facts-only 策略不自动扩权；留出逐项结果保持隔离 | S4 接入产品权限前 |
| 纵向历史与删除 | 复用既有历史/Artifact 及原生引用保留；删除导致不可重放时明确失效/重新建基，不自动清理或偷偷永久保留 | S5 改变现有窗口恢复/保留行为前 |
| 真实验收与切换 | 确定性验证先行；真实 Provider 的目标/样本/费用口径、部署与夜间启用分别确认 | S6 外部请求或生产变更前 |

上线按“新二进制离线验证 -> 当前数据只读影子比较 -> 经确认发布 -> 后续事实核对”的顺序。影子阶段不得改变正在运行的 Graph、Plugin、assistant、生产策略或夜间启停。读写版本不匹配则具名不就绪，不自动重置数据根；保留旧发行准确字节供现有回退路径使用，但不能让旧 writer 在已写新格式后盲目续写。

本轮结束的定义是：S0-S6 对应验收闭合，当前文档准确披露 S7/业务评分和真实净收益边界。完成代码、本地确定性通过、发行接入、真实 Provider、持续生产效果是不同状态；不使用一个“100% 完成”合并它们。
