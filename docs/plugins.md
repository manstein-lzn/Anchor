# Plugin：能力库与首期架构

状态：**首期基础链路已实现并通过结构性验收。** 本文集中维护 Plugin 的约定、实现范围和后续边界。知识库编译不在本期范围内。现有执行机制见 [当前架构](architecture.md)，操作方式见 [使用指南](usage.md)。

## 概念与职责

Anchor 的核心概念是 Graph、AgentNode、OpNode、Plugin。

| 概念 | 职责 |
| --- | --- |
| Graph | 组织节点之间的依赖、路由与反馈 |
| AgentNode | 由模型理解任务、判断和执行，显式引用所需 Plugin |
| OpNode | 执行确定的程序操作，不挂载 Plugin |
| Plugin | 可复用的做事规范与方法，以及可选的知识资源和工具引用 |

Plugin 不是第三种执行节点，不拥有运行工作区，也不自行调度任务。只有指导说明、没有工具的 Plugin 同样有效。Agent 和 OpNode 可以使用同一工具实现，但不必因此共享一个“能力节点”抽象。

Plugin 直接挂在 AgentNode 上，不挂在共享角色上；不引入默认继承、覆盖或合并规则。当前 Graph 中的 `agents` 仍是模型和任务指令的复用配置，不是另一套能力库。保存一个节点配置时，保存其 Plugin 引用即可。

能力说明讲“这类事情怎么做”，节点指令讲“这次负责什么”，工作区笔记讲“这次做到了哪里”。不把临时构造的 Bash 命令逐条登记成资产。

## 文件与唯一事实来源

数据根目录沿用服务的 `--root`。完整目录关系见 [当前架构](architecture.md) 的文件系统章节。

- `library/plugins/<id>/plugin.json`：名称、描述与工具引用。
- `library/plugins/<id>/instructions.md`：完整说明；可按需阅读目录中的补充资料。
- `library/tools/<id>/tool.json`：工具执行入口、环境与额外源代码目录。
- `library/environments/<name>/`：建议放置集中维护的工具环境；也支持引用已有的绝对路径环境。
- Graph 只保存 Plugin 标识，节点工作区不复制 Plugin 或环境。

Plugin 目录可以是指向权威源码目录的符号链接，例如仓库中的 [学术调研 Plugin](../plugins/academic-research/plugin.json)。目录内部的符号链接首期拒绝，防止补充资料意外指向资源范围之外。工具、说明均由操作者通过文件维护；WebUI 提供选择与只读查看。

多个 Plugin 可以引用同一工具。提示词目录、摘要和运行记录是来源的派生信息，不是另一份可独立维护的定义。

## 配置格式

Plugin 标识就是库内目录名，由字母、数字、点、下划线和连字符组成，首字符为字母或数字。名称用于显示，标识用于引用。

`library/plugins/academic-research/plugin.json`：

```json
{
  "name": "学术调研",
  "description": "检索原始论文，核验证据并形成可追溯的研究判断。",
  "tools": ["scholarly"]
}
```

说明统一放在同目录的 `instructions.md`。纯指导 Plugin 可以省略 `tools` 或设为空数组。

Graph 中的 AgentNode：

```json
{
  "id": "investigate",
  "agent": "researcher",
  "plugins": ["academic-research"]
}
```

不声明 `plugins` 的旧图继续按现有方式执行。OpNode、子图引用节点或 `agents` 角色中声明 `plugins` 会被拒绝；子图内部的 AgentNode 可以声明，展开后保留引用。新示例见 [plugin-research.json](../examples/graphs/plugin-research.json)。

## 渐进式披露与沙箱入口

运行时只把已挂载 Plugin 的名称、简述和说明入口注入 Agent 指令，不预加载完整说明。Agent 通过已有 Bash 工具按需读取：

```text
系统指令中的 Plugin 目录
    → /plugins/<id>/instructions.md
    → 更细的资料或工具用法
    → /tools/<tool-id>/run
    → /workspace 中的任务产物
```

Plugin 与工具资源只读挂载。节点未选择的 Plugin 不会出现在其自动生成的目录或专属挂载中；不把整个库暴露给节点。网络仍由节点的 `network` 决定，挂载 Plugin 不会自动打开网络。

目录由节点配置重新解析，反馈轮次和恢复时重新提供；完整说明可以再次读取，不声称模型永远记得看过的内容。本期验证跨节点、暂停与恢复的可访问性；真实模型在长上下文压缩后是否恰当重读，仍需后续专项验收。

## 工具与环境

工具入口在沙箱里统一为 `/tools/<id>/run`，不会把多个工具环境的 `bin` 混入一个 PATH。工具目录中的文件可从 `/tools/<id>/files` 只读访问。

`tool.json` 示例，路径必须替换为本机实际安装位置：

```json
{
  "entrypoint": "/opt/anchor/library/environments/research/bin/anchor-scholarly",
  "environment": "/opt/anchor/library/environments/research",
  "imports": []
}
```

- `entrypoint` 必填，指向可执行文件；可以是绝对路径或相对本工具目录的文件。
- `environment` 可选。声明时使用绝对路径，入口必须位于该环境内。Python venv 的解释器链接及安装目录会只读提供给沙箱，保持原路径以兼容 shebang。
- `imports` 可选，是需要额外只读提供的绝对路径，例如 editable 安装所需的包源码；不是授权节点访问任意主机目录的接口。

不同 Python 或依赖要求使用不同环境，同一环境跨节点、跨运行复用。工具命令在调用节点的工作区执行，任务输出相互隔离。纯脚本或二进制无需声明 Python 环境；依赖原位置的辅助文件应显式提供。

**本期接入已有环境，不实现自动依赖安装或升级服务。** 操作者准备一次环境并登记，运行时不创建任务专用 `.venv`。复杂容器、远程协议适配及通用安装器待真实工具需求出现再做。

为兼容旧图，Anchor 自身的完成命令仍带入项目执行环境，原有 `anchor-scholarly` 因而仍可能通过旧命令路径可用。新 Plugin 使用显式工具入口；Plugin 清单描述配置关系，不是 Bash 的全部权限白名单。尚未将旧内置工具从项目环境彻底拆出。

## 运行记录、更新与恢复

每次运行在 `plugins.json` 中保存按节点解析的 Plugin 名称、标识、说明资源内容摘要和工具来源摘要。它只记录执行配置，不复制 Plugin 的完整说明或环境。运行详情展示这份记录，不用当前库覆盖历史。

Plugin 说明、工具自带文件与导入源码按内容摘要核对，环境按安装文件的路径、大小、修改时间和 inode 核对。恢复及进入节点前若检测到变化，会明确拒绝继续，要求使用匹配资源或开始新运行。环境摘要用于发现正常安装或编辑变化，不是抵御恶意保留时间戳修改的完整内容证明。

**运行期间不要修改所引用的 Plugin、工具或环境。** 本期没有热更新、资源锁或原子环境切换器，也不承诺单条长命令执行期间检测每一次外部修改。资源核验发生在恢复与节点进入边界。带 Plugin 的运行同时核对展开图定义和子图轮次配置，变化时拒绝恢复并保留旧记录；旧调度仍读取当前 Graph，恢复前不应修改图结构。

引用不存在、说明缺失、工具入口不可执行或挂载非法时，保存／触发或运行会给出具体错误，不自动安装替代工具，不回退宿主机执行。不引入图发布版本或不可变 Plugin 版本体系。

## UI 与文件维护

WebUI 中选择 AgentNode 后，可以刷新 Plugin 库、勾选挂载项和读取当前说明。画布显示挂载数量；编排与运行共用这一显示。运行详情的 Plugin 页显示本次运行的解析记录。

界面区分配置与执行事实：挂载记录不证明工具已被调用，也不证明任务成功；具体执行仍查看对话与工具命令。首期不增加网页 Plugin 编辑器、独立市场或权限审批平台。

## 本期验收与后续边界

| 要求 | 本期验证方式 |
| --- | --- |
| 引用与复用 | Graph 保存／展开保留引用；两个节点读取同一 Plugin，无节点副本 |
| 按需披露 | 初始指令含目录但不含完整说明；执行时读取原文件 |
| 只读边界 | 真实 Bubblewrap 中读取成功、写入被拒绝、无其他 Plugin 挂载 |
| 工具隔离 | 两个含冲突依赖的 Python 环境从独立入口执行，跨节点复用 |
| 错误与恢复 | 无效引用不启动任务，资源变化拒绝恢复，旧记录保留 |
| UI | 真实 API 下选择、保存、查看说明及运行记录；加载与错误可见 |

2026-09-25 验证：267 项不使用真实模型服务的后端测试通过，19 项前端单元测试通过，4 项浏览器测试通过，前端构建、Ruff 与 mypy 通过。[Plugin 测试](../tests/test_plugins.py)使用真实沙箱检查共享、只读、环境依赖隔离及恢复拒绝；[浏览器验收](../apps/web/e2e/plugins.spec.ts)启动独立真实 API，执行选择、保存、说明预览、桌面／窄屏检查，并用脚本模型运行真实文献工具的帮助入口与 Git 提交。

这些结果证明基础接入链路，不证明真实模型已完成深度研究，也不证明不同 Python 主版本的所有工具都兼容。已验证两个独立 Python 环境中的冲突依赖隔离；跨解释器版本以及长上下文压缩后的自主重读仍需针对实际工具与模型验收。

知识库编译、统一查询格式、图文表证据结构全部暂缓。本期可以用普通说明和补充文件，不创建空知识库服务或提前冻结 schema。后续接入时仍要求统一取证入口、来源定位和原始证据保留。

后续优先补齐真实模型长上下文行为验收，以及按真实工具需要完善环境准备；不恢复归档中的其他产品方向。最终已验证范围与限制随实现更新本文。
