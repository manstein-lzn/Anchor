# 减少 Run 查询中的重复解码与历史提交复制

长会话的历史全量快照读取已由 PR #4 收敛，但每次 Run 查询仍多次解码当前状态，恢复投影还会复制已缓存的全部提交。网页轮询会反复制造这些临时对象，使多线程分配器留下更多空闲空间。

本次让一次读取共用已解码记录和同一份 frontier 预览，恢复投影借用历史条目，详情复用当前视图与时间，列表逐条读取并只保留响应字段。每条记录仍完整校验，通用旧视图投影仍重新读取现场。没有修改持久格式、成本计算、恢复算法或生产分配器配置。

新增的 `FileStore::with_record_entries` 替代恢复查询对完整 `Vec<RecordEntry>` 的深复制，并成为原 `record_entries` 的共同实现；没有新的缓存或持久事实。`frontier_from_record` 共用原 `prepare`，仍在临时副本上预览，不维护另一套执行规则。

验证和四组隔离对照见同目录 README.md 与测量 JSON。arena 参数只用于新建测试进程，生产配置由运维工作流单独部署。
