## 三、核心发现（可直接进论文）

### 1. 演化的驱动力（Q1）
不是单向"学习型取代解析式"，而是三条咬合的线索：
- **微架构复杂度**使解析模型逐代重写、误差放大；学习型模型以真机实测吞吐为监督直接拟合（Ithemal：Haswell 上 74% 的 basic block 优于 llvm-mca/IACA）。
- **表示能力竞争性迭代**：序列模型（Ithemal，token+层次 LSTM）→ 图表示+GNN（GRANITE，显式建模依赖，跨多微架构单模型）。
- **张量程序域动机不同**：不是精度本身，而是"用少量真机测量覆盖巨大搜索空间"（Ansor）；近期转向数据高效（TCL 主动学习取约 10% 样本）与轨迹感知（world model）。

机制共性：**监督信号来自真实硬件测量，模型嵌入搜索循环充当过滤/排序器**。注意：驱动力中"精度瓶颈 vs 工程成本"谁占主导，尚无全文级因果证据，写时应表述为机制性推断。

### 2. 三层次的程序表示 / 学习目标 / 训练信号（Q2）
- **指令级**：表示=指令 token 序列（Ithemal）或依赖图（GRANITE）；目标=basic block 稳态吞吐回归；信号=x86 真机微基准（BHive 系数据集、nanoBench 工具）。GRANITE 覆盖域仅 x86-64。
- **循环/张量**：表示=schedule/sketch+annotation 的层次化变换（Ansor）、或 schedule primitive 序列（TLP，把调度原语序列当序列语言处理）；目标=候选程序排序/回归；信号=真机测量（Ansor/AutoTVM）、复用已有 schedule（Transfer-Tuning）、静态分析（Tuna）、子图家族共享样本（FamilySeer）。
- **编译遍决策**：这里要**辨析"策略模型 vs 代价模型"**——MLGO 用 RL 策略直接出内联决策（奖励=二进制体积，最多减 7%）；MLGOPerf 用二级模型 IR2Perf 预测函数级加速比来**生成奖励**；LoopTune 用 RL 直接输出张量遍历序变换（APEX_DQN 明显优于 PPO）；RL4ReAl 多智能体 RL 做寄存器分配。关键点：可立即计算的目标（体积）能端到端学策略，不可立即计算的延迟目标**迫使引入学习型代价模型当奖励代理**。

### 3. 泛化（Q3）
- **跨硬件**是张量域被反复独立提出的中心问题：TLP 称之为 cross-hardware unavailability，诊断是特征绑定了硬件架构（解法：用天然跨硬件的 schedule primitive 序列）；TCL 当作数据/更新问题（主动采样+持续学习）。两条路线归因不同，**说明领域对"为什么不迁移"尚无共识**。
- **跨程序**：MLGO 声称在去重语料上泛化好；MLGOPerf 只在 SPEC CPU2006（train 生成、ref 评测）。
- **跨阶段**：零证据。
- **跨测量协议**是隐蔽陷阱：uiCA 显示按展开方式采集训练的模型（Ithemal、DiffTune）在含循环的 BHiveL 上排名变差——训练信号与部署定义的错配会伪装成"泛化失败"。

### 4. 信号获取谱系（Q4）
从准到便宜：真机测量（nanoBench/BHive，昂贵）→ perf 剖析（MLGOPerf，函数级耗时占比×调用次数，采集以天计，设 <1% 过滤）→ 模拟器（McGovern，Alpha 真机交叉验证）→ 静态分析（Tuna）→ 离线轨迹（offline 模仿学习）。
因果链已清晰：**因为信号必须实测且昂贵，研究重心从"模型结构"转向"样本选择与表示压缩"**。TLP 用 TenSet（8.65M 程序、重复率仅 1.04%）证明表示层冗余低，查表省不了样本。偏差与可重复性**无任何量化数字**。

### 5. 学习型 vs 解析式的证据冲突（Q5，论文核心张力）
- 学习型一侧：Ithemal/GRANITE 主张精度更优（GRANITE 平均测试误差 6.91，比前一 SOTA 改进 1.7，训练/推理吞吐约 3×）。
- 解析式一侧：uiCA 摘要称既有模型平均误差 9%–36%、自身通常约 1%；Facile 称同等 SOTA 精度下快近两个数量级且可归因到具体瓶颈；PALMED 显示白盒参数（端口/资源映射）本身可自动推断（Skylake 上 754 条指令→567762 次测量→9 个等价类），削弱"学习才自动化"的论证。
- **所有的对比数字口径不一、从未同台**（吞吐定义、BHiveU/BHiveL 版本、微架构集合都不同）。可写的结论是"协议混淆 + 分工"，不是胜负：**分界在 IR 层次**——机器码层解析占优（精度/速度/可解释），MLIR/张量层解析模型维护成本过高而被学习型采用。

### 6. 搜索集成与误差传播（Q6）
嵌入方式三类：①代价模型作候选打分器；②决策即策略（RL 直接出动作，代价只作奖励）；③代理型（Mind Mappings 用解析参考模型标注数据训可微代理，目标是搜索可行而非预测真实）。
**误差传播（预测误差→搜索排序颠倒→端到端退化）在本轮证据中完全为零**，是本主题最薄的一环，必须在论文里明确标为开放问题。

### 7. 评估协议（Q7）
- 指令级已有初步协议共识：BHive 系公共测量底座（30 万级 basic block，Ivy Bridge/Haswell/Skylake），但不同工具构建的数据集无法混合。
- 张量域缺统一协议：Transfer-Tuning 不得不把"Ansor 完整调优时间所达性能"定义为最大可达加速来构造参照。
- CompilerGym 是对 pass/flag 层缺标准环境的直接回应（GCC 11.2.0 动作集 2281；用确定性代码大小奖励而**非运行时间**，是代理目标与真实目标的显式取舍）。
- **数据泄漏与目标硬件过拟合无任何审计**；能确认的只是 MLGOPerf 显式用了 train 生成/ref 评测、LoopTune 报告了 80/20 划分。

### 8. 开放问题（Q8）
- **LLM 目前是优化机会的发现器/判别器，不是可校准的代价模型**：LLM 差分测试报出 4 个流水线级 + 12 个跨版本 bug；LOOPRAG 承认 LLM 在循环变换上频繁出错，改用符号特征+RAG+BM25 打分；LightCode 即便面向 LLM 推理编译仍用参数化解析代价模型。把 LLM 当显式代价模型并与解析/GNN 对比精度开销，**是空白**。
- 可迁移表示（TLP/41）；不确定性量化（解析路线天然输出"吞吐下界+关键路径上界"区间，学习型多输出点估计）；在线自适应（Pruner 的在线动量适配）。

## 四、遇到的问题 / 坑（务必先读）

1. **访问是最大瓶颈**。IEEE 大量返回 202、ACM DL 大量 403，很多关键工作（GRANITE、Facile、BHive、Crop、NeuroVectorizer、Halide 自动调度器）只有摘要/题录级，不能进对比表数字列。
2. **arXiv HTML 抽取系统性剥离公式与评测表**，读到的方法章节多、评测数字少。经验：**优先作者主页/机构仓库/出版社开放 PDF**（Springer PDF 成功过，IEEE 多次失败）。
3. **OpenAlex/Crossref 的引用图对本主题基本失效**：Ithemal 的 cites 只返回 LSTM/GloVe 等 ML 基础文献；cited_by 偏向硬件热点。唯一有效的引用图用法是**对 IISWC/CGO/PLDI 类基准论文做 cited_by**（如对 GRANITE 做 cited_by 才拿到 Facile/RL4ReAl）。有效检索形态是 **arXiv 上 `abs:`/`ti:` 精确短语 + 领域术语**，以及对数据集名（"BHive"）做 Crossref 检索。
4. **负结果为零**：没有"学习型不如解析式""误差被放大""目标硬件过拟合"的可引用来源。论文的冲突一节目前只能靠协议层证据（吞吐定义错配）支撑，不是胜负结论。
5. **对比表多数列仍无法填数**：表示/模型族/训练信号三列可定性填；端到端收益、编译开销、泛化评估三列**几乎没有可核验数字**。写作时宁缺勿造，缺的标注"证据不足"。
6. 注意材料里有**重复条目**（GRANITE 的 citation 2 与 24、Facile 的 26 与 61 同 id；Round 1 的题录与后来取得的全文版本），回填引文时要去重。
