# 认知交接实验

**问题**：在一个长任务的中途，接任者拿到**一份受限的认知状态**，能不能像拿到**全部原始材料**一样继续？
还是说压缩必然丢失接任者需要的东西？

这是认知层存在的唯一理由。如果答案是否，那这一层不值得建；如果答案是"某些形状能，某些不能"，
那么能的那一种就是我们要定义的。

**日期**：2026-09-11　**状态**：已完成三轮设计迭代，结果稳定

---

## 设计

在真实 run `f4eb8ac7` 上取一个切点——**首次写作尝试之前**。此时任务已积累 13 轮检索、
59 篇来源（24 篇读过全文）、74 条检索记录、24 组对立证据、123 条未解决项。

三个条件，**同一个全新 agent**（无工具、无记忆、无历史对话）、**同一套 7 个问题**
（原始 Anchor 的质量判据）、**同一份 agent instructions**：

```
A  原始材料      这个 run 累积的全部内容，逐字（write 节点的真实声明输入）
S  结构化摘要    模型从同一材料压缩出的"给接任者的进展总结"
B  认知状态      模型从同一材料压缩出的、按认知义务组织的状态
```

S 与 B **由同一个模型从同一份材料生成**，所以比较的是 **schema**，不是"谁写的"。

七个问题（原始 Anchor §12）：

1. 长期目标是什么？什么明确在范围之外？
2. 当前什么是已确立的？什么是不确定或冲突的？什么是受阻的？
3. 用户当前想要什么？
4. 哪些决策与约束仍然主导选择？
5. 哪些失败路径不可重复？在什么条件下才允许重试？
6. 当前的缺口是什么？下一个具体动作是什么？
7. 昂贵而省略的细节可以在哪里精确恢复？

评分：**盲评**——评分器只看一份回答和事实清单，不知道它来自哪个条件。

---

## 结果

三轮独立运行，每轮每条件 3 次，共 27 次评分：

| 条件 | 材料规模 | 三次得分 | 均值 |
|---|---:|---|---:|
| **A** 原始材料 | 141,033 字符 | [15, 20, 18] | **17.7** |
| **S** 结构化摘要 | 5,045 字符 | [6, 6, 9] | **7.0** |
| **B** 认知状态 | 4,762 字符 | [22, 21, 18] | **20.3** |

### 两条站得住的结论

**① 在同样尺寸下，schema 决定一切：7.0 vs 20.3，相差约 3 倍。**

S 与 B 是同一模型从同一材料生成的，规模几乎相同（5,045 vs 4,762 字符）。
差距**远在噪声带之外**（S 的区间 6–9，B 的区间 18–22，不重叠）。

> **"给接任者写一份好总结"与"按认知义务组织状态"不是同一件事，前者只拿到后者的三分之一。**

**② 认知状态用 3% 的体积，达到或超过原始材料。**

141,033 → 4,762 字符（3.4%），均值 20.3 vs 17.7。
**但这两者的区间重叠**（B 18–22，A 15–20），所以"B 优于 A"是弱信号；
**站的住的是"B 不劣于 A，而体积只有 3.4%"，且答话耗时少 1.5–3 倍。**

### 差异集中在哪里（三轮一致）

| 问题 | A | S | B |
|---|---:|---:|---:|
| 7 细节在哪可以精确恢复 | **1/5** | 2/5 | **5/5** |
| 4 仍然主导的约束 | 6/7 | 0–2/7 | 5/7 |
| 2 已确立/冲突/受阻 | 4/6 | 5/6 | **6/6** |

**第 7 问是结构性的**：原始材料**无法描述自己的索引**——它就是细节本身。
一个能说出"细节在何处、以何形式"的层，是原始材料在结构上给不出的。

## 三轮设计迭代（每一步都暴露了一个缺陷）

| 轮次 | 设计 | 暴露的缺陷 | 修正 |
|---|---|---|---|
| 1 | 手写 S 与 B，严格评分（"是否逐字陈述"） | 评分器把**正确的改述判为缺失**（A 用"约 59 条来源"被判未陈述）；A 得 12/31 | 评分改为"读者能否从中得到" |
| 2 | 手写 S 与 B，公正评分 | **S 是我写的，且只有 996 字符 vs B 的 1,814**——比的是内容多少，不是 schema | S 与 B 改由模型生成 |
| 3 | 模型生成 S 与 B，公正评分 | 单次运行的**绝对分数波动很大**（A 在同材料下 12 → 22 → 17） | 每条件重复 3 次，报区间 |

**这三步本身就是这个实验最值得保留的部分**：一个看起来显然的实验，连续三次设计都有致命缺陷，
而每一次的结果在当时都"看起来很像结论"。

## 第二个实验：行为测试（`behavioral.py`）

考卷有个未被打破的循环性：**七个问题定义了状态的 schema**，所以"按判据组织的状态满足判据"
多少是自证。要打破它，必须改测**产出**。

三个条件交给同一个接任者，要求它**真的写出论文**。这次判据是**交付物的要求**
（论证主线 / 机制解释 / 对比表 / 冲突证据 / 可操作开放问题）——与七问判据不同。

**每个条件都得到一个受账本管理的读取工具**（按节分页读账本）。这一条是必须的：
给不能解引用的节点一堆引用是没用的，而不给工具就对 B 不公平。

### 结果

```
条件     材料       正文      交付要求   结构错  行文错   输入token    合计token    相对A
A    141,033     13,975      5/5       0     0       69,553      97,628      —
S      5,045     15,197      5/5       0     0      260,904     286,885    +194%
B      4,762     14,721      5/5       0     1      504,094     535,575    +449%
```

### 两条结论

**① 考卷不预测产出。**

三个条件**都满足全部 5 项交付要求**——**包括考卷只拿 7/31 的 S**。
逐条判断理由具体（三篇的"总体问题"都是"缺少同台对照与负结果"，是真实的批评，不是橡皮图章）。

> **七问判据与"能否做好这件活"不相关。它测的是能否复述任务，不是能否完成任务。**

**② "小状态 + 按需取回"没有省钱，反而贵 3–5 倍。**

```
工具循环每次调用都重发整段对话。
取回进循环的细节按【轮次】计费；写进初始 prompt 的细节只计一次。
```

**A 的接任者几乎不需要取回**（材料本来就在 prompt 里）；**B 的接任者必须一节一节取**，
而每一次取回都进入对话、在后续每一轮重发。

**而且产出质量完全一样。为同样的结果多付了 3–5 倍。**

> 这直接否定了"把细节外置、按需取回"这个直觉——**也是本白皮书投影公式的一个未解决缺陷**：
> 它写明"投影不包含完整工件内容"，但没有说**取回的代价在工具循环里按轮次放大**。

### 直接的架构要求

```
取回的内容不得在对话里累积。
取回必须是一次性使用、用后即弃——或者先在循环外处理完再进上下文。
否则"小上下文"只是把成本从 prompt 搬到了循环里，并乘以轮次。
```

这一条与本项目早先实测到的现象同源：工具循环重发前缀是主要的成本来源。

## 这个实验**不能**说明什么

**① 判据的循环性未被打破。**

七问判据定义了 B 的 schema，所以"按判据组织的状态满足判据"多少是自证的。
**它不能证明这七个问题是继续工作的正确判据。**

要证明那一点，需要**行为测试**：让接任者真的去写，再评价产出——而不是出考卷。
本实验没有做，因为让只有引用的接任者写出带正确引用的论文，要求它**能解引用**，
而那是一项执行能力扩张（见下）。

**② 接任者无法解引用。**

B 的 Knowledge Index 说"细节在账本的 sources / evidence_notes / tensions 里"，
但本实验里的接任者**没有取回能力**。所以它只能复述状态里写了的东西。

这既是本实验的局限，**也是一个真实的设计约束**：休眠引用对没有解引用能力的节点毫无用处
（与第一轮评审的指正一致）。真实系统里，接任者要么预先拿到物化片段，要么有受账本管理的读取能力。

**③ 样本是 1 个 run、1 个任务类型，行为测试每个条件各一次。**

**⑤ 行为测试里接任者都拿到了读取工具。** 所以它测的是"状态能否被**行动**"，
不是"状态是否自足"。若撤掉工具，三个条件的产出都会塌——这不是状态的问题，是能力的问题。

**④ 绝对分数不可当基准**，只有排序与区间有意义。

## 复现

```bash
export ANCHOR_DATABASE_URL="sqlite:///$PWD/.local/api.sqlite"
TAKEOVER_REPEAT=3 .venv/bin/python experiments/cognition_takeover/run.py
```

产出 `results.json`（含每份回答与逐条评分）、`derived_S.md`、`derived_B.md`。
成本约 20 次模型调用。

原始材料从 `context_snapshots` 经 store 的公共接口读取，与运行时自己读快照的方式一致。
