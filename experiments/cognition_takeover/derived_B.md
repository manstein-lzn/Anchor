## Situation

已确立：
- 主线不是"学习型单向替代解析式"，而是按 IR 层次分工。机器码层：参数化解析/仿真模型仍占据精度—速度—可解释性前沿，且其参数获取已高度自动化（微基准自动推断，无需手工，所以"手工"指的是模型结构而非参数来源）。高层 IR（MLIR/张量）层：opcode 语义离硬件太远，解析建模维护成本过高，学习型成为可行路径。
- 三层证据密度不同。指令级最完整：存在三条并行子谱系（序列/GNN 学习型；参数化解析—仿真；自动微基准与端口映射推断）。张量层中等：表示正从"程序静态结构 + 硬件专家特征"转向"编译器对程序做了什么"（schedule primitive 序列）；动机不是精度本身，而是"用少量真机测量覆盖巨大搜索空间"，重心已移到样本选择与预算分配。编译遍决策层最薄：主要是 RL 策略模型直接产出决策，代价模型降级为奖励生成器。
- 广泛共识：监督信号来自真实硬件测量；其物质基础是低开销微基准工具链。
- 一条可写成一手发现的协议效应：测量/吞吐定义不一致本身会改变模型排名——按展开方式采样训练的模型在含循环基准上表现变差。结论是"谁更准"必须先固定协议。

尚不确定或相互冲突：
- 同一基准上"学习型 vs 解析式"的直接对照数字为零。uiCA 的"约 1% 对 9%–36%"、Facile 的"快近两个数量级"、GRANITE 的"6.91 / 1.7 / 3×"都只到摘要级，或口径不明（1.7 的单位在 HTML 抽取中丢失）。
- 演化驱动力是精度瓶颈还是工程/维护成本，只有机制性推断。
- 三处归因分歧未决：张量层不迁移是表示问题（TLP 一派）还是数据与更新方式问题（TCL 一派）；指令级精度是模型族问题还是输入依赖分析问题（CesASMe/AnICA 主张后者）；"学习型 vs 解析式"的二分是否错置了问题（RL 直接决策可绕过显式代价模型）。
- 代理真值/代理奖励的偏差未量化：可微代理以解析模型为真值；RL 环境用代码大小替代运行时间。
- "模型误差是被搜索吸收成更长的调优时间，还是转化为更差的最终代码"——语料中没有任何一条测量了这条传播链。
- LLM 分支目前只有机制性对立（LLM 推理编译仍用参数化解析代价模型；循环变换用符号打分约束 LLM），无对照实验。

## Experience

- OpenAlex 的 cited_by 对 Ithemal / AutoTVM / MLGO 这类"系统名或 arXiv 种子"只返回 ML 基础文献或硬件加速器热点。仅当种子是 IISWC/CGO/PLDI 类基准或硬件测量论文（GRANITE、Facile、BHive）时才重试 cited_by——这是唯一被证明有效的引用图用法。
- OpenAlex 的 cites（后向参考文献）在本主题上只返回通用背景。仅当目标是追溯"搜索算子/学习器族谱系"时才重试；唯一有价值的命中是模拟退火与 GBDT 两条谱系锚点。
- Crossref 的 query.bibliographic：裸系统名零命中；含引号的数据集/基准名命中过一次。仅当查询式内含引号的数据集/基准名加 venue 或标题词时重试。
- arXiv 宽泛英文组合词几乎全噪声（LLM 系统自身成本、量化、语音识别等）。仅在字段限定精确短语（abs:"…" / ti:"…"）与领域术语 AND 组合时重试。
- arXiv HTML 全文会系统性剥离表格与公式，并在评测章节处截断。仅用 HTML 读方法与机制章；需要评估数字时必须换作者主页/机构仓库/会议官方 PDF；若只有 HTML，按 offset 分段续读，不要指望一次取回评测表。
- IEEE Xplore 链接反复返回 HTTP 202。未先找到公开版本（arXiv / 作者页 / 机构库）就不要为 IEEE 链接花读取预算。dl.acm.org 稳定 403，只能走 arXiv 或作者版。Springer PDF 可读，出版社开放 PDF 值得优先尝试。
- 不要为取数反复读同一篇而不读完整；每轮至少预留一次读取落在评估章节，否则数值列永远填不上。
- 抽象级/题录级来源可以记录，但不得进入对比表数值列。禁止把摘要级数字当作已核实结论。
